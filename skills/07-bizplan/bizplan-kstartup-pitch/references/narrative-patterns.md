# narrative-patterns.md — 스토리라인 패턴 + 본문→피치덱 추출 매핑

## 1. 17장 기본 구조 (디바이더 4장 포함)

```
S1   L1 Cover           표지
S2   L2 Divider 01      Problem
S3   L3 Content         문제 정의
S4   L4 Number          문제 규모 (수치)
S5   L2 Divider 02      Solution
S6   L3 Content         솔루션 개요
S7   L3 Content         작동 방식
S8   L5 Compare         차별점 비교
S9   L2 Divider 03      Market & Strategy
S10  L3 Content         타깃 고객
S11  L4 Number          시장 규모 (TAM/SAM/SOM)
S12  L3 Content         진입 전략
S13  L4 Number          매출·수익 모델
S14  L5 Compare         자금 소요·조달
S15  L2 Divider 04      Team
S16  L6 Team            팀 구성
S17  L7 Closing         비전·CTA
```

기본 17장. 발표 시간 단축 시 디바이더 또는 L3 일부 슬라이드를 제거.

## 2. 본문(.docx) → 피치덱 추출 매핑

`bizplan-kstartup` 본문 12개 소항목 → 피치덱 13장 (디바이더 제외) 매핑.

| 본문 항목 | 피치덱 슬라이드 | 추출 규칙 |
| --- | --- | --- |
| 1-1 개발 동기·목적 | S3 문제 정의 (L3) | 본문 [문제 정의] 단락 → 글머리 3개로 분해 |
| 1-2 외부 환경 | (피치덱 생략) | 본문에만 포함, 피치덱 별도 슬라이드 없음 |
| 1-3 목표시장 | S10 타깃 고객 (L3) + S11 시장 규모 (L4) | [목표 고객 정의] → S10 / [시장 규모] 표 → S11 대형 숫자 |
| 2-1 현황 | (S6 일부 흡수) | 준비 수준 한 줄로 압축 → S6 마지막 글머리 |
| 2-2 실현 방안 | S6 솔루션 개요 (L3) + S7 작동 방식 (L3) | [핵심 기능 ①②③] → S6 본문 / [개발 단계] → S7 본문 |
| 2-3 차별화 | S8 차별점 비교 (L5) | [경쟁자 비교표] → 그대로 L5 표로 변환 |
| 3-1 자금 계획 | S14 자금 소요·조달 (L5) | [자금 소요·조달 표] → 그대로 L5 표로 변환 |
| 3-2 진입·성과 | S12 진입 전략 (L3) + S13 매출 (L4) | [진입 단계] → S12 글머리 / [매출 목표] → S13 대형 숫자 |
| 3-3 추진 일정 | (S12 일부 흡수) | 핵심 마일스톤 1줄 → S12 마지막 글머리 |
| 4-1 팀 현황 | S16 팀 구성 (L6) | [대표자] + [팀원] → 카드 2~4개로 변환 |
| 4-2 외부 협력 | (S16 일부 흡수) | 주요 협력처 1줄 → S16 카드 하단 캡션 |
| 4-3 인력 운용 | (피치덱 생략) | 본문에만 포함 |

### 추출 알고리즘

```
1. .docx에서 PSST 12개 소항목 텍스트 추출
2. 각 소항목 → 위 매핑 테이블에 따라 슬라이드별 입력값 객체 생성
3. 슬라이드 입력값 객체를 L1~L7 함수에 전달
4. .pptx 생성

생략 항목(1-2, 4-3)은 본문에는 포함되지만 피치덱에서는 제외.
짧은 항목(2-1, 3-3, 4-2)은 별도 슬라이드 없이 인접 슬라이드에 흡수.
```

### 입력값 객체 예시

```javascript
// 본문 1-1에서 S3 슬라이드 입력값 추출
const s3Input = {
  title: "이런 문제가 있습니다",
  subtitle: "{타깃 고객}이 겪는 불편",
  bullets: [
    extractFirstSentence(body["1-1"], "[문제 정의]"),
    extractCase(body["1-1"]),
    extractGap(body["1-1"]),
  ],
};
L3_Content(pres, s3Input);
```

## 3. 스토리라인 패턴 (3종)

기본 17장 구조 위에 강조점만 다르게 배치하는 변형 패턴.

### 패턴 A — Problem-First (B2C·사회문제)

기본 구조 그대로 사용. 문제 → 솔루션 → 시장 → 팀 순서. 심사위원에게 문제의 절박함을 먼저 각인시키는 방식.

**적용 조건**
- 일반 소비자 대상 서비스
- 사회적 문제 해결형
- 정성적 공감이 중요한 경우

**조정점**
- S3~S4 (문제) 슬라이드에 사례·인터뷰 인용 추가
- S6 솔루션 슬라이드는 "이런 방식으로 해결합니다" 톤

### 패턴 B — Traction-First (검증된 초기기업)

기본 구조에서 S16(팀) → S2 직후로 이동. 팀·성과 → 솔루션 → 시장 순서. 이미 사용자·매출이 있는 팀이 신뢰를 먼저 쌓는 방식.

**적용 조건**
- 초기 매출·사용자 데이터 보유
- 대표자·팀의 도메인 경력이 강점
- 재도전성공패키지 신청 등 경험 강조 케이스

**조정점**
- S2 디바이더 직후 "Team & Traction" 슬라이드 1장 추가
- S3~S4 문제 슬라이드 분량 축소

### 패턴 C — Market-First (B2B·기술 기반)

기본 구조에서 S10~S11(시장) → S2 직후로 이동. 시장 기회 → 솔루션 → 전략 순서. 시장 규모와 기술 우위로 설득하는 방식.

**적용 조건**
- B2B SaaS·기업 솔루션
- 명확한 시장 규모 데이터 보유
- 기술 차별성이 핵심 경쟁력

**조정점**
- S11 시장 규모 슬라이드를 도입부로 이동
- S8 차별점 슬라이드에 기술 우위 지표 추가
- S6~S7 솔루션 분량 확대

## 4. 패턴 선택 의사결정

```
[질문 1] 매출·사용자 등 검증 데이터가 있는가?
  YES → 패턴 B (Traction-First)
  NO  → 다음 질문

[질문 2] 고객이 일반 소비자인가, 기업인가?
  소비자 → 패턴 A (Problem-First)
  기업   → 패턴 C (Market-First)
```

3개 패턴 중 자동 추천 후 사용자 최종 선택을 받는다.
