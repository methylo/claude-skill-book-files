# 메타 필드 관리 가이드

lecture-research v3에서 도입된 두 가지 메타 필드(`visualizable_as`, `expires_at`)의 작성·관리 가이드.

---

## 1. visualizable_as — 시각화 적합도 사전 표시

### 목적

각 자료에 대해 "어떤 시각화 형태로 슬라이드에 들어갈 수 있는가"를 리서치 단계에서 미리 표시한다. lecture-blueprint 단계에서 시각화(V) 결정의 입력으로 활용해, "수치는 있는데 슬라이드에 못 넣는 자료" 문제를 사전 방지한다.

### 5가지 V 코드

| 코드 | 의미 | 적합 자료 |
|---|---|---|
| V-CHART | 차트(막대·선·도넛) | 3개 이상 항목 비교, 시간 추이, 비율 분포 |
| V-DIAGRAM | 다이어그램(플로우·관계도) | 구조·관계·프로세스, 개념 도식 |
| V-IMAGE | 이미지·스크린샷 | 도구 화면, 결과물, 시연 컷 |
| V-TABLE | 표(비교표·체크리스트) | 다항목 비교, 분류 매트릭스 |
| V-TEXT | 텍스트(불릿·인용) | 단일 수치, 개념 정의, 짧은 인용 |

### 자료 유형별 권장 코드

| 자료 유형 | 1순위 | 2순위 | 비고 |
|---|---|---|---|
| 데이터 포인트 (3개 이상 항목) | V-CHART | V-TEXT | 항목 부족 시 V-TEXT |
| 데이터 포인트 (단일 수치) | V-TEXT | - | V-CHART 부적합 |
| 외부 사례 | V-IMAGE | V-TEXT | 결과물 있을 때 V-IMAGE |
| 본인 사례 | V-CHART | V-DIAGRAM | 운영 데이터는 V-CHART, 흐름은 V-DIAGRAM |
| 비교 매트릭스 | V-TABLE | V-CHART | 수치 위주면 V-CHART |
| 반박과 응답 | V-DIAGRAM | V-TEXT | 구조적 응답은 V-DIAGRAM |
| 핵심 개념 | V-DIAGRAM | V-TEXT | 관계 있으면 V-DIAGRAM |
| 도입 훅 | V-IMAGE | V-TEXT | 사례형이면 V-IMAGE |

### 작성 규칙

- 한 자료에 1~2개 코드 부여 (3개 이상 부여 금지 — 결정 미루기)
- 1순위와 2순위가 있으면 둘 다 표시 (예: `V-CHART, V-TEXT`)
- 적합도가 떨어지더라도 V-TEXT는 항상 가능 (백업)

### 분포 점검

전체 RL 노트 작성 후 visualizable_as 분포를 점검한다.

```yaml
visualization_distribution:
  V-CHART: 12
  V-DIAGRAM: 8
  V-IMAGE: 6
  V-TABLE: 4
  V-TEXT: 10
```

**경고 신호**

| 패턴 | 진단 | 조치 |
|---|---|---|
| V-TEXT만 가능 자료 70% 초과 | 자료가 시각적으로 빈약 | 데이터 포인트·비교 매트릭스 추가 수집 |
| V-CHART 10% 미만 | 수치 데이터 부족 | 슬롯 3 데이터 포인트 보강 |
| V-IMAGE 0건 | 시연·결과물 자료 없음 | 도구 스크린샷·결과물 사례 추가 |
| 5종 중 2종 이하만 등장 | 시각 다양성 부족 | 부족한 V 종류 자료 보완 |

## 2. expires_at — 자료 만료일 관리

### 목적

각 자료가 언제 다시 검증·갱신되어야 하는지 미리 표시한다. AI 영역은 6개월이면 통계가 낡고, 도구 UI는 3개월이면 바뀐다. 만료일 없이 1년 전 RL을 그대로 쓰면 강의 신뢰도가 떨어진다.

### 카테고리별 권장 만료 주기

| 자료 카테고리 | 권장 만료 | 이유 |
|---|---|---|
| AI 도구 정보 (UI·기능) | +3개월 | 업데이트 빠름, 화면 변동 |
| AI 통계·시장 데이터 | +6개월 | 시장 데이터 분기별 갱신 |
| 외부 사례 (기업·기관) | +6개월 | 결과·맥락 재확인 필요 |
| 본인 사례·경험 | +12~24개월 | 강의자가 직접 갱신 가능 |
| 개념 정의 (학술·표준) | +12개월 | 비교적 안정 |
| 인용·격언 | +24개월 | 거의 불변 |
| 가격 정보 | +3개월 | 가격 정책 변경 빈번 |
| 비교 매트릭스 (도구) | +3개월 | 도구 변화 반영 |
| 비교 매트릭스 (방법론) | +12개월 | 비교적 안정 |

### 작성 규칙

- 모든 자료에 `expires_at: YYYY-MM-DD` 형식으로 표시
- 자료 수집일 기준으로 카테고리별 권장 주기 적용
- 강의자가 추가 검증 의무 있는 자료는 명시적으로 짧게 (예: 도구는 3개월)

### 만료 점검 체크리스트

RL 작성 직후 다음 점검:

- [ ] 모든 자료에 `expires_at` 표시
- [ ] 6개월 이내 신선한 자료가 50% 이상
- [ ] 3개월 이내 만료 예정 자료 개수 명시
- [ ] 12개월 초과 자료는 사유 명시 (장기 유효 사례·인용 등)

### 옵시디언 Dataview 쿼리 (선택)

만료 예정 자료를 한눈에 보려면 다음 Dataview 쿼리를 별도 노트에 둔다.

```dataview
TABLE expires_at as "만료일", source_li as "강의"
FROM "10 외부 강의"
WHERE type = "lecture-research"
  AND expires_at <= date(today) + dur(30 days)
SORT expires_at ASC
```

이 쿼리는 30일 이내 만료 예정 자료를 가진 RL 노트를 보여준다.

### 만료된 자료 처리 흐름

```
RL 노트 만료 자료 발견
  ↓
같은 자료를 다른 강의에서 또 쓸 예정인가?
  ├─ 예 → 해당 자료를 갱신 (web_search 재실행)
  └─ 아니오 → 만료 표시만 유지 (재사용 안 할 거면 갱신 불필요)
```

## 3. 메타 필드 통합 통계 (YAML 프론트매터)

RL 노트의 YAML 프론트매터에 다음 통계를 자동 집계한다.

```yaml
slot_stats:
  data_points_count: 12          # 슬롯 3 총합
  data_categories_covered:        # 4카테고리 중 커버
    - 시장
    - 사용
    - 비용
    - 시간
  ab_case_ratio: 75              # 슬롯 4 A·B 등급 비율 (%)
  own_case_ratio: 60             # 슬롯 5 본인 사례 보유 꼭지 비율 (%)
  comparison_matrix_count: 2     # 슬롯 6 매트릭스 개수
  rebuttal_count: 8              # 슬롯 7 반박 총합

visualization_distribution:       # 자료별 V 코드 집계
  V-CHART: 12
  V-DIAGRAM: 8
  V-IMAGE: 6
  V-TABLE: 4
  V-TEXT: 10

expiry_summary:
  fresh_within_6m: 80            # 6개월 이내 신선한 자료 비율 (%)
  expires_within_3m: 5           # 3개월 이내 만료 예정 자료 개수
```

이 통계는 관문 2 검증의 9·10번 항목 자동 판정에 사용된다.

## 4. 사용자 결정이 필요한 시점

다음 상황에서는 자동 처리하지 않고 사용자에게 확인한다.

### visualizable_as

- 한 자료에 V-CHART와 V-DIAGRAM 둘 다 가능한 경우 → 메시지 의도에 따라 결정 필요
- 자료가 너무 추상적이라 V 코드 부여가 어려운 경우 → 자료를 보강할지 V-TEXT 처리할지 결정

### expires_at

- 카테고리 분류가 모호한 자료 (예: AI 도구 사용자 후기 — 도구냐 사례냐) → 더 짧은 주기 적용 권장
- 강의자 본인 사례가 12개월 미만 만료 — 강의자가 갱신 가능한지 확인
- 1차 자료 출처가 사라진 경우 (URL 링크 깨짐) → 재검색 또는 자료 폐기 결정

## 5. 메타 필드 적용 단계별 효과

처음에는 메타 필드 작성이 부담스러울 수 있다. 단계별 효과를 정직하게 안내.

| 시점 | RL 작성 시간 | 슬라이드 적합도 | 자료 재사용성 |
|------|-------------|----------------|--------------|
| 도입 직후 (1~3회차) | +20% (메타 작성 부담) | +10% | +5% |
| 3~5회차 | +10% | +30% | +20% |
| 5~10회차 | +0% | +50% | +50% |
| 10회차 이후 | -10% (Atom 인용 가능) | +60% | +70% |

처음 1~3회는 부담만 있고 효과는 미미하다. 5회차부터 RL 작성 효율과 슬라이드 적합도가 명확히 개선된다. 10회차부터는 Atom 노트 풀과 결합되어 새 강의 작성 시간이 단축된다.

## 6. 사용자 선호 반영

작성자 선호와 정합:

- 결정 기준 제시형 메타 필드 (정의·기준·결과 중심)
- 추측·과장 금지 (자료 등급 명확화)
- 코드 블록 안 메타 표기 시 마크다운 기호 금지 — YAML 표준 형식만
- 한국어 설명, 메타 코드는 영문 표준 (V-CHART 등 국제 호환)
