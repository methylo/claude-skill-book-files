# 시각 소재 수집 가이드 (슬롯 10)

lecture-research v3.1에서 강화된 슬롯 10(슬라이드 시각 소재)의 수집 가이드. v3.0의 약점이었던 "글 위주 슬라이드 양산" 문제를 정면 보완한다.

---

## 왜 슬롯 10 강화가 필요한가

기존 v3.0의 슬롯 10은 "이미지 키워드 3~5개"만 적는 수준이었다. 그 결과:

- 슬라이드 만들 때 키워드만 보고 즉흥적으로 이미지 검색
- 검색해도 적합한 이미지가 없어서 V-TEXT 슬라이드만 양산
- 도식·차트는 키워드만으로 만들기 어려워 결국 빈 슬라이드 또는 텍스트로 대체

v3.1은 슬롯 10을 **3가지 소재 유형(이미지·도식·차트)으로 분리**해서, RL 단계에서 실제 사용 가능한 소재까지 수집한다.

---

## 3가지 소재 유형

### 10-1. 이미지 소재 (V-IMAGE 후보)

#### 수집 항목

| 유형 | 수집 내용 |
|------|----------|
| 도구 스크린샷 | 공식 페이지 캡처 또는 실제 사용 화면 |
| 결과물 사례 | Before/After, 결과물 시리즈 |
| 시연 화면 | 라이브 데모용 단계별 캡처 |

#### 작성 양식

| # | 소재 설명 | 소스(URL 또는 직접 제작) | 라이선스 | 사용 슬라이드 추정 |
|---|----------|------------------------|----------|--------------------|
| I1 | Claude 화면 스크린샷 | https://claude.ai/... 직접 캡처 | 공식 사용 가능 | Ch1 슬라이드 3 |
| I2 | 마케팅 카피 Before/After | 직접 제작 (강의자 실제 작업물) | 강의자 소유 | Ch1 슬라이드 5 |
| I3 | 도구 4종 비교 화면 | 각 사 공식 페이지 4장 | 공식 사용 가능 | Ch2 슬라이드 7 |

#### 수집 기준

- 꼭지당 1개 이상 (최소)
- 라이선스 명시 필수: 공식·CC·강의자 직접 제작·기관 허가
- 검증 가능한 URL 또는 직접 제작 메모
- 저작권 위반 자료 사용 금지 (단순 구글 이미지 검색 결과는 제외)

#### 라이선스 안전 자료 출처

| 출처 | 용도 |
|------|------|
| 도구 공식 페이지 | 도구 스크린샷·로고 (공식 사용 가능) |
| Unsplash·Pexels | 일반 분위기 이미지 (CC0) |
| 정부 공공 데이터 | 통계·지도 (공공 자료) |
| 강의자 직접 캡처·제작 | 결과물·시연 (강의자 소유) |
| 기관 사전 허가 자료 | 기업 사례 (서면 허가) |

### 10-2. 도식 소재 (V-DIAGRAM 후보)

#### 수집 항목

도식은 검색해서 가져오는 것이 아니라 **구조를 설계**하는 것이다. RL 단계에서 다이어그램의 노드 구성과 관계선까지 미리 작성한다.

#### 작성 양식

| # | 시각화 형태 | 노드 목록 | 관계선 | 사용 슬라이드 추정 |
|---|------------|----------|--------|--------------------|
| G1 | 수평 플로우 4단 | 도구 분석 → 작업 매핑 → 도구 선택 → 결과 검증 | 단방향 화살표 | Ch1 슬라이드 4 |
| G2 | 2분할 비교 | (왼쪽) 기존 방식 / (오른쪽) 신규 방식 | 양방향 비교 | Ch1 슬라이드 6 |
| G3 | 중앙 방사형 | 중심: 핵심 메시지 / 주변: 4가지 적용 영역 | 중심 → 주변 | Ch2 슬라이드 9 |

#### 6가지 시각화 형태

lecture-slides의 다이어그램 레이아웃 체계와 정합. 다음 6종 중 하나 선택.

| 형태 | 적합 메시지 | 노드 수 |
|------|------------|---------|
| 수평 플로우 | 단계별 프로세스 | 3~5개 |
| 수직 파이프라인 | 절차·순서 | 5~8개 |
| 중앙 방사형 | 허브-스포크 | 중심 1 + 주변 3~6 |
| 2×N 매트릭스 | 카테고리 × 속성 | 2~5 × 3~6 |
| 타임라인 | 시간 흐름 + 마일스톤 | 4~7 시점 |
| 계층 트리 | 분류·체계 | 3계층 이내 |

#### 수집 기준

- 꼭지당 1개 이상 (이미지 또는 차트와 합쳐 시각 소재 2개 이상)
- 노드 텍스트 미리 작성 (각 노드당 ≤ 20자)
- 관계선 방향 명시 (단방향 / 양방향 / 무방향)

### 10-3. 차트 소재 (V-CHART 후보)

#### 수집 항목

차트는 **슬롯 3 데이터 포인트와 직접 연결**된다. V-CHART 가능 표시된 데이터를 차트 형태로 변환할 때 필요한 정보를 미리 정리.

#### 작성 양식

| # | 차트 형태 | X축 데이터 | Y축 데이터 | 출처 데이터 포인트 | 사용 슬라이드 추정 |
|---|----------|-----------|-----------|-------------------|--------------------|
| C1 | 막대 (세로) | 도구 4종 | 정확도 % | D1, D3 | Ch1 슬라이드 7 |
| C2 | 선 | 시점 (분기별) | 사용자 수 | D2 | Ch1 슬라이드 2 |
| C3 | 도넛 | 카테고리 5개 | 비율 % | D5 | Ch2 슬라이드 5 |

#### 5가지 차트 형태

lecture-slides의 차트 체계와 정합.

| 형태 | 적합 데이터 | 데이터 포인트 수 |
|------|------------|----------------|
| 막대 (세로) | 항목 비교, 순위 | 3~7개 |
| 막대 (가로) | 항목명 길거나 7개 이상 | 7~12개 |
| 선 | 시간 추이 | 5~12 시점 |
| 도넛 | 비율 (합 100%) | 3~6개 |
| 영역 | 누적 추이 | 5~12 시점 |

#### 수집 기준

- 슬롯 3 데이터 포인트 중 V-CHART 표시된 것 모두 차트 소재로 매핑
- X축·Y축 데이터 명시 (단위 포함)
- 출처 데이터 포인트 ID 매핑 (D1, D2 등)

## 시각 소재 수집의 실제 작업 흐름

### Step 1. 슬롯 3·4·5·6 채움 후 시작

데이터·사례·본인 사례·비교 자료가 다 채워진 뒤에 슬롯 10을 작성한다. 거꾸로 하면 시각 소재가 자료와 어긋난다.

### Step 2. visualizable_as 기반 1차 매핑

- visualizable_as에 V-IMAGE 표시된 자료 → 10-1 이미지 소재 후보
- visualizable_as에 V-DIAGRAM 표시된 자료 → 10-2 도식 소재 후보
- visualizable_as에 V-CHART 표시된 데이터 → 10-3 차트 소재 후보

### Step 3. 부족한 유형 보강

각 꼭지에서 다음을 점검한다.

| 점검 | 부족 시 보강 방법 |
|------|------------------|
| 이미지 소재 0개 | 도구 공식 페이지 직접 검색, 강의자 직접 캡처 |
| 도식 소재 0개 | 핵심 개념을 6가지 시각화 형태 중 하나로 구조화 |
| 차트 소재 0개 | 슬롯 3 데이터 포인트 중 비교 가능한 것 차트화 |

### Step 4. 라이선스·검증

- 모든 이미지 소스에 라이선스 표시
- URL은 검증 가능한 형태로 (단축 URL·임시 링크 금지)
- 직접 제작 자료는 강의자 보관 위치 명시

## 시각 소재 분포 점검

전체 RL 작성 후 다음 분포를 점검한다.

```yaml
visual_source_count:
  image: 12
  diagram: 8
  chart: 6
```

### 정상 분포 (4개 꼭지 강의 기준)

- 이미지: 8~16개 (꼭지당 2~4개)
- 도식: 4~8개 (꼭지당 1~2개)
- 차트: 4~8개 (꼭지당 1~2개)

### 경고 신호

| 신호 | 진단 | 조치 |
|------|------|------|
| 이미지 0건 | 시연·결과물 자료 부족 | 도구 스크린샷·결과물 보강 |
| 도식 0건 | 구조·관계 시각화 부족 | 핵심 개념 도식화 |
| 차트 0건 | 수치 데이터 시각화 부족 | 슬롯 3 데이터 포인트 차트화 |
| V-TEXT만 가능 자료 70% 초과 | 시각적으로 빈약한 강의 | 데이터·비교·이미지 보강 |
| 한 꼭지에 시각 소재 1개 이하 | 슬라이드 단조로움 위험 | 이미지·도식 보강 |

## lecture-blueprint와의 연계

슬롯 10의 시각 소재는 lecture-blueprint 매핑표 작성 시 직접 입력으로 사용된다.

- 매핑표의 시각화(V) 칸에 슬롯 10의 소재 ID(I1, G1, C1) 직접 인용
- bridge가 시각화 형태를 결정할 때 임의 추측 없이 슬롯 10에서 가져옴
- 슬롯 10에 없으면 bridge 단계에서 사용자에게 추가 수집 요청

이렇게 RL 단계에서 시각 소재가 고정되면 lecture-slides 단계의 "이미지가 없어 V-TEXT 양산" 문제가 사라진다.

## 시각 소재 수집이 어려울 때

### 케이스 1. 도구 스크린샷이 너무 자주 바뀐다

→ 강의 직전 1주일 이내에 직접 캡처 (만료일 1개월로 짧게)
→ 또는 도구 화면 대신 결과물·플로우 다이어그램으로 대체

### 케이스 2. 결과물 사례가 부족하다

→ 강의자 본인 작업물 활용 (가장 안전, 라이선스 문제 없음)
→ 또는 텍스트 기반 결과물(글·코드)을 코드 블록으로 표시 (V-TEXT)

### 케이스 3. 도식 구조가 안 떠오른다

→ 다이어그램 6가지 레이아웃 중 가장 단순한 것부터 (수평 플로우 또는 2분할 비교)
→ 핵심 개념을 3~4단어로 압축한 뒤 그 사이 관계선만 그리기

### 케이스 4. 차트로 만들 데이터 포인트가 부족하다

→ 슬롯 3에서 비교 가능한 데이터 추가 검색
→ 또는 슬롯 6(비교 매트릭스)을 차트로 변환

## 사용자 선호 반영

작성자 선호와 정합:

- 결정 기준 제시형 (3가지 소재 유형이 명확하게 분리됨)
- 추측·과장 금지 (라이선스 명시·검증 가능 URL)
- 한국어 작성, 시각화 코드(V-IMAGE 등)는 영문 표준
- 직접 제작 자료 우선 (강의자 16권 책·블로그 운영 자산 활용 가능)
