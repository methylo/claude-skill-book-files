lecture-research v3에서 추가된 4개 슬롯의 작성 패턴과 예시 가이드. Phase 4 슬롯 채우기 단계에서 참조한다.

## 슬롯 3. 데이터 포인트

### 작성 원칙

- 사례에 포함된 수치는 슬롯 4(대표 사례)에 두고, **사례와 분리된 시장·산업 데이터**만 여기에 둔다
- 한 데이터 포인트 = 한 줄 = 한 출처 = 한 시점
- 단위·시점 명시 필수 ("70% 증가"가 아니라 "2024년 대비 2025년 70% 증가")

### 4가지 카테고리

#### 카테고리 1. 시장 (Market)

시장 규모·성장률·사용자 수·점유율·매출 등 거시 지표.

**예시**
- "AI 글쓰기 도구 시장 규모: 2024년 28억 달러 → 2026년 67억 달러 (Gartner 2026-Q1, A2)"
- "ChatGPT 월간 활성 사용자: 4억 명 (OpenAI 공식 2026-04, A1)"
- "Claude 일평균 메시지 수: 2025년 대비 2026년 3배 (Anthropic 2026-Q1, A1)"

**우선 검색 출처**: Gartner, Statista, McKinsey, IDC, 정부 보고서, 기업 IR 자료

#### 카테고리 2. 사용 (Usage)

평균 사용 시간·빈도·채택률·활용 패턴 등 미시 지표.

**예시**
- "전문가 평균 AI 도구 사용 빈도: 주 12회 (Stack Overflow 2025 Survey, B)"
- "프롬프트 평균 길이: 280자 (OpenAI 사용자 분석 2025, A1)"
- "기업 AI 도구 채택률: 직원 100명 이상 73% (McKinsey State of AI 2026, B)"

**우선 검색 출처**: Stack Overflow Survey, McKinsey State of AI, 사용자 분석 리포트

#### 카테고리 3. 비용 (Cost)

가격·절감 효과·투자 규모·ROI.

**예시**
- "AI 코딩 도구 평균 가격: 월 20달러 (각 사 공식 가격 페이지 2026-04, A1)"
- "기업 AI 도입 투자: 평균 280만 달러 (Deloitte 2026, B)"
- "콘텐츠 제작 비용 절감: 35% (HubSpot 2025 보고서, B)"

**우선 검색 출처**: 기업 공식 가격 페이지, Deloitte·PwC·HubSpot 산업 보고서

#### 카테고리 4. 시간 (Time)

작업 시간 변화·학습 시간·도입 기간.

**예시**
- "코드 작성 시간 단축: 평균 55% (GitHub Copilot 2024 Research, B)"
- "마케팅 카피 작성 시간: 4시간 → 30분 (HubSpot 2025, B)"
- "AI 도구 학습 곡선: 평균 2~4주 (Anthropic 사용자 인터뷰, A1)"

**우선 검색 출처**: GitHub Research, 기업 사례 보고서, 사용자 인터뷰

### 수집 체크리스트

- [ ] 꼭지당 3개 이상
- [ ] 4카테고리 중 2카테고리 이상 커버
- [ ] 같은 출처 데이터 2개 이상 금지 (출처 분산)
- [ ] 모든 데이터에 등급(A1/A2/B)·시점·visualizable_as·expires_at 표시
- [ ] C 등급 출처 데이터 포인트로 사용 금지

### 시각화 적합도 판단

- 3개 이상 항목 비교 → V-CHART
- 2개 이하 또는 단일 수치 → V-TEXT
- 시간 추이 → V-CHART (선)
- 비율 분포 → V-CHART (도넛)

## 슬롯 5. 본인 사례·경험

### 작성 원칙

- 강의자가 직접 운영·관찰한 1차 데이터만
- 추측·일반화 금지. 실제 운영 기록 기반
- 외부 사례보다 신뢰도 높음 (강의자가 답변 가능)

### 4가지 본인 사례 유형

#### 유형 1. 운영 사례

블로그·커뮤니티·강의·수업 등 강의자가 직접 운영한 활동.

**예시 (저자 기준)**
- 카카오 AI 책쓰기 커뮤니티 1,500명 운영 1년 관찰
- 개인 블로그 방문자·체류시간 패턴
- LiveKlass 3차 강좌 수강생 반응 패턴
- 16권 책 집필 과정의 도구 사용 변화

#### 유형 2. 실험 사례

직접 도구를 테스트하거나 비교한 실험.

**예시**
- 같은 프롬프트를 3개 도구에 입력해 결과 비교
- A/B 테스트로 콘텐츠 전환율 비교
- 스킬 적용 전/후 작업 시간 측정

#### 유형 3. 관찰 사례

강의·코칭 중 수강생에게 관찰한 패턴.

**예시**
- 50명 수강생 중 80%가 도구 사용법만 묻고 워크플로우 질문은 20%만
- 초급자가 가장 자주 막히는 지점 3가지
- 중급 → 고급 전환의 분기점

#### 유형 4. 기록 사례

장기간 누적된 메모·기록에서 도출한 패턴.

**예시**
- 옵시디언 볼트 노트 누적 패턴
- 1년치 강의 후기에서 반복되는 키워드
- 책 출간 시점별 시장 반응

### 작성 양식

```markdown
#### 본인 사례 N

**맥락**
- 운영/실험/관찰/기록 중 어디에 해당
- 규모 (인원·기간·횟수)
- 시점 (언제부터 언제까지)
- 강의자 역할

**관찰**
- 구체적 수치 또는 패턴 (1~3개)
- 일반화 가능한 부분만 (개인 특수 상황 제외)

**강의 활용**
- 어느 메시지의 근거인지 명시
- 어느 슬라이드에 들어갈지 (가능하면)

**메타**
- visualizable_as: V-{코드}
- expires_at: 12~24개월 권장 (강의자가 직접 갱신 가능)
```

### 예시 (저자 기준)

```markdown
#### 본인 사례 1: AI 책쓰기 커뮤니티 운영 1년

**맥락**
- 운영 사례
- 규모: 카카오톡 커뮤니티 1,500명
- 시점: 2024-04 ~ 2026-04
- 역할: 운영자·콘텐츠 제공자

**관찰**
- 회원 질문 80%가 "어떤 도구 쓰면 되나요"
- 워크플로우·맥락 질문은 전체의 20%만
- 책 1권 완성한 회원 중 90%가 "도구보다 흐름"이 핵심이었다고 회고

**강의 활용**
- "도구가 아니라 흐름이 중요하다" 메시지의 직접 근거
- Ch2 핵심 슬라이드에 인용

**메타**
- visualizable_as: V-CHART (질문 비율) / V-TEXT
- expires_at: 2027-04-01
```

### 본인 사례가 없을 때

모든 꼭지에 본인 사례를 채우려고 무리하지 말 것. 다음 경우에는 "본인 사례 없음 — 외부 사례로 대체"를 명시한다.

- 청중 직무가 강의자 영역과 거리 있음 (예: 의료·법률·제조업 특화)
- 신규 도구·기능에 대한 강의 (강의자 사용 경험 부족)
- 매우 일반적·기초적 개념 (예: AI 정의)

단 강의 전체에서 본인 사례 비율이 50% 미만이면 강의자의 강점이 약해짐 → 사례 보강 권장.

## 슬롯 6. 비교 매트릭스

### 작성 원칙

- 모든 꼭지에 필요하지 않음. 비교형 메시지가 있는 꼭지에만
- 비교 항목 2~5개, 속성 3~6개가 가독성 한계
- 셀 내용 30자 이내 (슬라이드 표로 옮길 때 제약)

### 3가지 매트릭스 유형

#### 유형 1. 도구 비교

도구·서비스·플랫폼 간 기능·가격·특성 비교.

**예시**
| 항목 | ChatGPT | Claude | Gemini |
|------|---------|--------|--------|
| 입력 한계 | 32K | 200K | 1M |
| 출력 일관성 | 중 | 상 | 중 |
| 한국어 자연도 | 중 | 상 | 중 |
| 가격(월) | $20 | $20 | $20 |

#### 유형 2. 방법론 비교

접근법·전략·프레임워크 비교.

**예시**
| 항목 | 프롬프트 모음 | 스킬 시스템 | 코워크 |
|------|--------------|-------------|--------|
| 재현성 | 낮음 | 높음 | 매우 높음 |
| 학습 곡선 | 낮음 | 중간 | 높음 |
| 확장성 | 낮음 | 높음 | 매우 높음 |
| 적합 단계 | 입문 | 중급 | 고급 |

#### 유형 3. 시간·단계 비교

Before/After·이전/이후·기존/신규 비교.

**예시**
| 단계 | 이전 (GPT 시대) | 이후 (Claude 시대) |
|------|----------------|-------------------|
| 책 1권 작업 시간 | 6개월 | 3개월 |
| 도구 수 | 5~8개 | 1~2개 |
| 결과물 일관성 | 중 | 상 |
| 협업 가능성 | 낮음 | 높음 |

### 메타 필드

- 출처: 직접 테스트 / 공식 문서 / 보고서
- 등급: A1·A2·B
- visualizable_as: V-TABLE 우선, 수치 비교만이면 V-CHART
- expires_at: 도구 비교는 3개월, 방법론은 12개월

### 비교 매트릭스 작성이 어려울 때

비교 데이터를 모으기 어려우면 메시지를 비교형이 아닌 정의형·기준형으로 재설계 권고. 예:

- ✗ "Claude vs ChatGPT 비교" (데이터 부족)
- ○ "AI 글쓰기 도구는 작업 단계로 선택한다" (정의형 → 비교 매트릭스 불필요)

## 슬롯 7. 주요 반박과 응답

### 작성 원칙

- 강의자가 듣고 싶은 질문이 아니라 **청중이 던질 의문**을 적는다
- 응답은 1~2줄로 짧게. 길어지면 본문에서 다룰 것
- 응답에 근거(데이터·사례·비교) 1개 이상 매핑 필수
- LI의 anti_lecture가 있으면 그 항목을 반박 1로 우선 배치

### 4가지 반박 유형

#### 유형 1. 회의형

"정말 그게 효과가 있나요?" / "다 거기서 거기 아닌가요?"

**예시**
- 반박: "AI 도구는 결국 다 비슷하지 않나요?"
- 응답: 작업 단계별 적합도가 다름 (입력·처리·출력 3축에서 차이)
- 근거: 슬롯 6 비교 매트릭스 1번
- visualizable_as: V-DIAGRAM (3축 도식)

#### 유형 2. 비용·효율형

"투자 대비 효과가 있나요?" / "시간 들여 배울 가치가 있나요?"

**예시**
- 반박: "프롬프트 잘 쓰는 법 배운다고 그게 일에 도움 되나요?"
- 응답: 같은 작업 35% 단축, 결과 일관성 향상 (외부 사례 + 본인 사례)
- 근거: 슬롯 3 D5 (시간) + 슬롯 5 본인 사례 2
- visualizable_as: V-CHART (작업 시간 비교)

#### 유형 3. 위협·우려형

"내 일이 없어지는 거 아닌가요?" / "보안 문제는 어떻게 해결하나요?"

**예시**
- 반박: "회사 자료를 AI에 넣으면 보안 문제 없나요?"
- 응답: 기업용 플랜은 학습에 사용 안 됨. 단 무료 플랜은 별도 점검 필요
- 근거: 슬롯 3 D6 + Anthropic·OpenAI 공식 정책 문서
- visualizable_as: V-TEXT

#### 유형 4. 대체·기존형

"기존 방식으로도 충분한데 굳이?" / "왜 바꿔야 하나요?"

**예시**
- 반박: "지금 쓰는 도구로도 잘 되는데 굳이 바꿔야 하나요?"
- 응답: 바꾸지 않아도 됨. 단 1년 후 격차가 벌어짐 — 학습 비용은 지금이 가장 낮음
- 근거: 슬롯 3 D2 (채택률 추이)
- visualizable_as: V-CHART (시간별 격차)

### 작성 양식

```markdown
#### 반박 N

- **청중 시점 의문**: "{문장}"
- **응답**: {1~2줄 답}
- **근거**: {슬롯 위치 또는 외부 자료}
- **visualizable_as**: V-{코드}
```

### 수집 체크리스트

- [ ] 꼭지당 2~3개
- [ ] 4유형 중 2유형 이상 커버
- [ ] 모든 반박에 근거 매핑
- [ ] 모든 반박에 응답 1~2줄 작성 (3줄 초과 금지)
- [ ] LI anti_lecture 항목과 연결 (있으면)

## 4개 신규 슬롯 통합 점검

신규 슬롯 작성을 마치면 다음 통합 점검을 한다.

| 점검 | 기준 |
|------|------|
| 데이터 포인트가 사례와 중복되지 않는가 | 슬롯 3은 사례와 분리된 거시 데이터만 |
| 본인 사례가 외부 사례를 압도하지 않는가 | 외부 50% + 본인 50% 균형 권장 |
| 비교 매트릭스가 데이터 포인트의 단순 재배치 아닌가 | 매트릭스는 비교 메시지의 직접 근거 |
| 반박이 강의자 입맛에 맞는 질문만 모은 게 아닌가 | 회의형·위협형 등 불편한 반박 포함 |

이 점검을 통과하면 lecture-blueprint로 진행한다.
