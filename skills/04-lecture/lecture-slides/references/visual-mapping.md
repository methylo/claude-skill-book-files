# 시각 자료 통합 매핑

Phase 4에서 [DIAGRAM]·[CHART] 태그가 붙은 슬라이드를 네이티브 도형으로 구성할 때 읽는다.

Phase 4에서 .pptx를 생성할 때, 시각화 대상 슬라이드를 식별하고 아래 레이아웃 매핑을 기준으로 pptxgenjs 네이티브 도형(addShape + addText)으로 직접 구성한다. SVG→PNG 이미지 변환을 사용하지 않으므로 서버 환경의 한글 폰트 유무와 무관하게 뷰어(PowerPoint) 측 시스템 폰트로 정상 렌더링된다. 별도 이미지 제작 단계 없이 Phase 4 안에서 완결된다.

**시각 자료 구분:**

| 구분 | 용도 | 태그 |
|------|------|------|
| 다이어그램 | 개념도·플로우차트·비교도·구조도·관계도 | `[DIAGRAM: 설명]` |
| 차트 | 수치 데이터 차트 (막대·선·도넛·영역) | `[CHART: 설명]` |

**실행 순서:**

1. **후보 식별**: Phase 3 구조에서 `[DIAGRAM: 설명]` 또는 `[CHART: 설명]` 태그가 붙은 슬라이드 + Phase 4 생성 중 시각화가 효과적인 슬라이드를 목록화한다
2. **유형 판단**: 각 후보의 내용에 따라 다이어그램·차트 구분과 레이아웃/차트 유형을 선택한다 (아래 매핑 참조)
3. **네이티브 도형 구성**: pptxgenjs의 `addShape()` + `addText()`로 다이어그램/차트 요소를 직접 구성한다. SVG→PNG 이미지 변환을 사용하지 않는다. 뷰어(PowerPoint) 측 시스템 폰트로 한글이 렌더링되므로 폰트 누락 문제가 발생하지 않는다
4. **레이아웃 구현**: 레이아웃 설계(노드 배치, 색상 규칙, 화살표 방향 등)는 아래 매핑을 따르고, 실제 구현은 pptxgenjs 네이티브 도형(ROUNDED_RECTANGLE, OVAL, RIGHT_ARROW 등)과 addText()로 수행한다. 색상은 슬라이드 악센트 색상과 동일하게 적용한다
5. **QA 검증**: markitdown으로 텍스트 내용 확인. PDF 변환 후 레이아웃 검수 시, 서버 환경에 한글 폰트가 없으면 프리뷰에서 한글이 깨질 수 있으나 실제 .pptx 파일은 정상이므로 레이아웃 배치만 확인한다

**다이어그램 레이아웃 매핑:**

| 슬라이드 내용 유형 | 다이어그램 레이아웃 |
|-----------------|----------------------|
| 비교/대조 (A vs B) | 2분할 비교 (좌우 카드) |
| 프로세스/단계 (Step 1→2→3) | 수평 플로우 |
| 기능·역할 매트릭스 | 체크리스트 매트릭스 (표) |
| 중심 개념 + 파생 항목 | 중앙 방사형 |
| 시간순 변화 | 타임라인 |
| 상위-하위 구조 | 계층 트리 |

**차트 유형 매핑:**

| 슬라이드 내용 유형 | 차트 유형 |
|-----------------|---------------------|
| 항목별 수치 비교 | 세로 막대 |
| 순위·길이 비교 | 가로 막대 |
| 시간 추이·변화 | 선 그래프 |
| 비율·구성 | 도넛 |
| 누적 변화 | 영역 그래프 |

**시각 자료 생성 기준:**
- 다이어그램: 노드 3~8개, 노드당 텍스트 20자 이내
- 차트: 데이터 포인트 최대 12개, 라벨 최대 15자, Y축 단위 필수
- 색상: 슬라이드 악센트 색상을 primary로, 연한 변형을 light로 사용
- 총 시각 자료 수: 강의당 4~10개가 적절. 모든 슬라이드에 넣는 것이 아니라 시각화가 내용 전달에 효과적인 슬라이드에만 적용한다
