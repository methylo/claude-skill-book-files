# 책쓰기 기획 워크플로우 (Book Planning Workflow)

집필 전 단계 전문. "아이디어를 발견하고 쓰기 전에 설계하는" 5단계 프로세스.

## 전체 흐름

```
Phase 1: 책 아이디어 발견 → Phase 2: 독자·시장 확인 → Phase 3: 콘셉트 정의 → Phase 4: 목차와 챕터 개요 → Phase 5: 출판 기획서 → Phase 6: 기획 인계 블록
```

사용자의 현재 상태를 파악해 적절한 단계부터 시작한다.
- 키워드·경험만 있거나 여러 아이디어 중 고르지 못함 → Phase 1부터
- 주제·방향 확정됨 → Phase 2부터
- 독자·유사서 확인 완료 → Phase 3부터
- 콘셉트 확정됨 → Phase 4부터
- 전체 구조 확정, 문서화만 필요 → Phase 5부터
- 기획서는 있고 후속 스킬로 넘길 인계 파일만 필요 → Phase 6부터

각 Phase 결과물은 대화창 텍스트로 제공한다. 문서 파일로 만드는 것은 Phase 5 출판 기획서 최종본과 Phase 6 기획 인계 블록 둘이다.

## 파이프라인 규약

책 프로젝트 폴더에 `00 파이프라인 규약.md`가 있으면, 파일명·문체 정본·역할 경계에서 이 스킬의 기본값보다 규약 파일을 먼저 따른다. 규약 파일은 선택 사항이다. 없으면 이 문서의 기본값으로 진행한다.

---

## 문체 기준

이 스킬은 기획 문서를 생성한다. 책 본문 집필 문체는 적용하지 않는다.

기획 문서 문체:
- 간결하고 명확한 서술. 한 문장에 하나의 정보
- 설득·논증형 톤. 기획서를 읽는 사람(출판사 편집자, 공저자, 본인)이 판단할 수 있는 근거를 제시한다
- 과장형 형용사, 모호한 부사, 추측 표현 사용 금지
- Phase 1~4 산출물은 실무 메모 톤, Phase 5 출판 기획서는 용도에 맞는 공식 톤

## Phase 1: 책 아이디어 발견

**목표:** 사용자가 제공한 키워드, 경험, 문제의식과 보유 자료를 확장하고 조합해 책으로 발전시킬 아이디어 후보를 찾는다.

이 단계에서는 콘셉트와 목차를 확정하지 않는다. 사용자가 주제와 방향을 이미 확정했다면 Phase 1을 건너뛰고 Phase 2로 이동한다.

### 1-1. 출발 재료 수집

이미 대화나 제공 자료에 포함된 내용은 재질문하지 않는다. 부족한 경우 아래 항목 중 필요한 것만 확인한다.

1. **주요 키워드:** 관심 있는 단어·현상·분야
2. **관심 이유:** 왜 이 주제를 계속 생각하는가
3. **저자 자산:** 관련 경험·전문성·관찰·실패·성과
4. **반복 질문:** 주변 사람이나 독자에게 자주 받은 질문
5. **보유 자료:** 글·강의·메모·사례·인터뷰·데이터
6. **제외 범위:** 다루고 싶지 않거나 쓸 수 없는 내용

키워드만 제공된 경우 모든 항목을 한꺼번에 묻지 않는다. 먼저 키워드를 확장하고, 후보를 구분하는 데 필요한 정보만 추가로 확인한다.

### 1-2. 주제 재료 확장

입력된 키워드를 단순 연관어가 아니라 책의 질문이 될 수 있는 방향으로 확장한다.

| 관점 | 확장 질문 |
|------|-----------|
| 독자 문제 | 이 주제와 관련해 독자가 반복해서 겪는 문제는 무엇인가 |
| 저자 경험 | 저자가 직접 겪거나 관찰한 장면은 무엇인가 |
| 통념과 이견 | 일반적인 설명과 다르게 보는 지점은 무엇인가 |
| 변화 | 독자는 읽기 전과 후에 무엇이 달라져야 하는가 |
| 방법과 기준 | 저자가 제시할 수 있는 판단 기준이나 실행 방법은 무엇인가 |
| 시대 맥락 | 지금 이 질문이 중요해진 이유는 무엇인가 |

근거가 없는 시장성이나 독자 반응은 단정하지 않는다. 확인이 필요한 내용은 `[확인 필요]`로 표시한다.

### 1-3. 주제군 형성

확장된 재료를 의미가 가까운 3~6개의 주제군으로 묶는다. 각 주제군에는 다음 내용을 제시한다.

```
[주제군 이름]
- 포함된 키워드·경험:
- 중심 질문:
- 예상 독자 문제:
- 책으로 확장할 수 있는 이유:
- 부족한 소재:
```

주제군은 목차가 아니다. 같은 재료를 서로 다른 독자 문제나 저자 관점으로 다시 묶는 것을 허용한다.

### 1-4. 책 아이디어 후보 생성

주제군을 바탕으로 방향이 겹치지 않는 책 아이디어 3~5개를 만든다.

```
[후보 1]
- 임시 제목:
- 중심 질문:
- 예상 독자:
- 독자가 겪는 문제:
- 저자가 제공할 관점:
- 확장 가능한 내용:
- 저자에게 적합한 이유:
- 예상 한계·확인할 점:
```

임시 제목의 표현만 바꾼 후보를 여러 개 만들지 않는다. 독자, 중심 질문, 접근 방식 중 하나 이상이 달라야 별도 후보로 인정한다.

### 1-5. 후보 비교와 선택

| 평가 기준 | 판단 질문 |
|-----------|-----------|
| 저자 적합성 | 이 저자가 직접 쓸 이유가 있는가 |
| 독자 문제 | 독자가 해결하고 싶은 문제가 구체적인가 |
| 확장성 | 한 권 분량으로 확장할 논점과 소재가 있는가 |
| 차별성 | 기존 설명과 다른 질문·경험·관점이 있는가 |
| 소재 보유 | 경험·사례·자료를 확보했거나 확보할 수 있는가 |
| 지속성 | 일시적 유행을 넘어 반복해서 읽힐 질문인가 |

후보별 강점, 약점과 추가 확인 사항을 근거와 함께 비교한다. 점수만으로 순위를 결정하지 않는다.

사용자에게 다음 선택지를 제시한다.

1. 후보 하나를 선택한다.
2. 두 후보의 요소를 결합한다.
3. 특정 후보를 더 탐색한다.
4. 새로운 방향으로 후보를 다시 만든다.

AI가 최종 후보를 임의로 확정하지 않는다. 사용자가 선택하거나 결합안을 승인한 경우에만 Phase 2로 이동한다.

### Phase 1 완료 기준

- 키워드·경험·문제의식이 여러 관점으로 확장되었다
- 주제군과 책 아이디어 후보가 구분되었다
- 후보별 가능성·한계·추가 확인 사항이 비교되었다
- 사용자가 진행할 아이디어를 선택하거나 결합안을 승인했다
- 선택 결과가 Phase 2의 입력으로 정리되었다

## Phase 2: 독자·시장 확인

**목표:** 이 책의 독자가 누구인지, 어떤 상태에서 이 책을 집어 드는지, 읽고 나서 무엇을 얻는지를 구체화한다.

### 2-1. 독자 프로필

아래 항목을 구조화한다:

| 항목 | 내용 |
|------|------|
| 핵심 독자 | 이 책을 가장 먼저 사는 사람 (직업·역할·상태) |
| 확장 독자 | 핵심 독자 주변에서 관심을 가질 수 있는 층 |
| 독자의 현재 상태 | 지금 어떤 문제를 겪고 있는가, 어떤 시도를 했는가 |
| 독자의 기대 | 이 책에서 무엇을 얻으려 하는가 |
| 읽은 뒤 변화 | 이 책을 읽고 나면 무엇이 달라지는가 |

### 2-2. 시장 분석

| 항목 | 내용 |
|------|------|
| 카테고리 | 서점 기준 분류 (예: 자기계발 > AI활용) |
| 유사서 3~5권 | 제목, 저자, 핵심 내용, 한계점 |
| 차별화 포인트 | 유사서와 비교한 이 책만의 고유 가치 |
| 시장 타이밍 | 지금 이 책이 나와야 하는 이유 |

### 유사서 조사 방법

사용자가 유사서를 이미 알고 있으면 그 정보를 활용한다. 유사서를 모르거나 부족한 경우:

1. **웹 검색 활용**: 주제 키워드 + 카테고리로 온라인 서점(교보문고, YES24, 알라딘)을 검색한다. 사용자에게 "유사서를 웹 검색으로 조사하겠습니다"라고 안내한 뒤 진행한다.
2. **카테고리 탐색**: 유사서가 명확하지 않으면, 해당 주제가 속할 서점 카테고리의 베스트셀러·신간을 조사해 후보를 추린다.
3. **인접 카테고리 확장**: 직접 유사서가 없는 신규 주제라면, 인접 카테고리에서 독자층이 겹치는 책을 대안으로 분석한다.

### Phase 2 완료 기준
- 핵심 독자가 구체적 인물상으로 설명된다 (직업·역할 수준)
- 유사서 대비 차별점이 한 문장으로 정리된다
- 사용자가 독자·시장 분석을 확인·승인한다

## Phase 3: 콘셉트 정의

**목표:** "이 책이 왜 필요한가"를 한 문장으로 정리한다.

### 입력 확인

Phase 1·2 결과를 그대로 입력으로 쓴다. 아래 항목을 다시 묻지 않는다.

| 항목 | 어디서 오는가 |
|------|--------------|
| 주제·아이디어 | Phase 1-5에서 사용자가 고른 후보 |
| 저자의 강점 | Phase 1-1 저자 자산 |
| 집필 동기 | Phase 1-1 관심 이유 |
| 독자와 읽은 뒤 변화 | Phase 2-1 독자 프로필 |
| 기존 유사서와의 차별점 | Phase 2-2 차별화 포인트 |

위 다섯 항목 중 비어 있는 것이 있을 때만 사용자에게 확인한다.

### 콘셉트 후보 설계

입력을 바탕으로 콘셉트 후보 2~3안을 만든다. 각 안은 같은 주제를 다른 각도에서 잡는다.

**콘셉트 한 문장 구조:**

```
[독자의 문제/상태] + [이 책이 제공하는 기준/관점] + [읽은 뒤 독자의 변화]
```

**후보 제시 양식:**

```
[안 1] 관점: ○○ 중심
콘셉트: (한 문장)
강점: 이 방향이 유리한 이유
약점: 이 방향의 한계

[안 2] 관점: △△ 중심
콘셉트: (한 문장)
강점: ...
약점: ...

[안 3] 관점: □□ 중심
콘셉트: (한 문장)
강점: ...
약점: ...
```

사용자가 하나를 선택하거나, 조합을 요청하면 최종 콘셉트를 확정한다.

### 콘셉트 확장

선택된 콘셉트를 3~5문장으로 확장한다:
- 이 책이 다루는 핵심 질문
- 기존 접근과 다른 관점
- 저자만이 쓸 수 있는 이유

### Phase 3 완료 기준
- 콘셉트 후보 2~3안이 제시되었다
- 사용자가 하나를 선택(또는 조합)하고 최종 콘셉트를 승인했다
- 최종 콘셉트 한 문장이 "누구에게, 무엇을, 왜"를 모두 포함한다

## Phase 4: 목차와 챕터 개요

**목표:** 콘셉트를 독자가 읽는 순서로 배열하고, 각 챕터의 논점·구성·소재를 집필 설계도 수준으로 구체화한다.

### 4-1. 전체 구조 설계

책의 흐름을 4단계로 나눈다:

| 단계 | 역할 | 챕터 수 (가이드) |
|------|------|------------------|
| 도입부 | 독자의 문제를 정의하고 이 책의 관점을 선언한다 | 1~2장 |
| 전개부 | 핵심 개념·방법론·기준을 순서대로 제시한다 | 3~5장 |
| 심화부 | 실제 적용 사례, 응용, 확장을 다룬다 | 2~3장 |
| 마무리 | 관점을 재정렬하고 독자의 다음 단계를 제시한다 | 1장 |

총 챕터 수는 책의 성격에 따라 조정한다. 실용서 기준 8~12장이 표준이나, 사용자 의도에 따른다.

### 4-2. 챕터별 개요

각 챕터에 대해 아래 구조로 작성한다. 핵심 논점 한 문장과 전체 흐름에서의 역할을 먼저 정하고, 나머지 항목을 채운다.

```
## Ch [번호]: [챕터 제목]

**핵심 논점:** 이 챕터가 답하는 질문, 독자가 얻는 한 가지 (1문장)

**흐름에서의 역할:** 앞 챕터와의 연결, 다음 챕터로의 전환

**도입 전략:** 어떤 장면·질문·사례로 시작하는가

**소제목 구성:**
  1. [소제목 1] — 다루는 내용 요약 (1~2문장)
  2. [소제목 2] — 다루는 내용 요약
  3. [소제목 3] — 다루는 내용 요약

**핵심 소재:** 이 챕터에서 사용할 사례·데이터·경험·인용 (있으면)

**마무리 전략:** 어떤 관점 전환 또는 다음 챕터로의 연결로 마무리하는가

**예상 분량:** 원고지 기준 매수 또는 A4 페이지 수
```

챕터 수가 많으면 핵심 논점과 흐름에서의 역할을 전 챕터에 대해 먼저 채운 뒤, 나머지 항목을 챕터 단위로 이어서 작성한다.

### 작성 원칙

- 소제목은 3~5개를 기본으로 한다. 챕터 성격에 따라 조정 가능
- 소제목명은 기능·현상이 아닌 **판단·행동 중심 문장**으로 작성한다
  - ❌ "AI 도구의 종류" → ✅ "도구 선택 기준이 결과를 결정한다"
- 핵심 소재는 저자의 경험·사례를 우선 배치한다. 사용자가 제공한 소재가 없으면 [소재 필요]로 표시한다
- 예상 분량은 정밀하지 않아도 된다. 상대적 비중(짧은/표준/긴)으로 표시해도 된다

### 4-3. 독자 관점 검증

목차 설계 후, Phase 2에서 정의한 핵심 독자의 시선으로 목차를 검증한다.

**검증 방법:** Phase 2에서 정의한 핵심 독자가 Ch 1부터 순서대로 읽는다고 가정하고, 챕터 간 연결을 점검한다.

```
Ch 1을 읽은 독자의 상태: "○○을 알게 되었다 / ○○이 궁금해졌다"
→ Ch 2로 넘어갈 동기가 있는가? [있다/없다 + 이유]

Ch 2를 읽은 독자의 상태: "..."
→ Ch 3로 넘어갈 동기가 있는가?

... (마지막 챕터까지)

마지막 챕터를 읽은 독자의 상태: "..."
→ Phase 3 콘셉트에서 약속한 변화와 일치하는가? [일치/불일치 + 이유]
```

검증 결과 끊기는 지점이 있으면, 챕터 순서 변경·추가·삭제를 제안한다.

### 4-4. 구조 점검 기준

독자 관점 검증과 별도로, 목차의 구조적 완성도를 점검한다:
1. **메시지 중복**: 서로 다른 챕터가 같은 내용을 반복하지 않는가
2. **균형**: 특정 챕터에 내용이 과도하게 집중되지 않는가
3. **완결성**: 도입에서 제기한 문제가 마무리에서 해소되는가

### Phase 4 완료 기준

- 전체 흐름(4단계)이 설계되었다
- 모든 챕터의 개요가 양식대로 작성되었다
- 핵심 논점이 1문장으로 정리되고 소제목이 판단·행동 중심으로 작성되었다
- 독자 관점 검증에서 끊기는 지점이 없거나, 발견된 지점이 조정되었다
- 사용자가 목차와 챕터별 개요를 확인·승인한다

## Phase 5: 출판 기획서

**목표:** Phase 1~4의 결과를 하나의 문서로 종합한다. 출판사 제안용, 자가출판 계획용, 내부 검토용 등 용도에 맞게 톤을 조정한다.

### 용도 확인

사용자에게 기획서 용도를 확인한다:
- **출판사 제안용**: 출판사 편집자가 검토하는 공식 문서. 시장성·차별점·저자 역량 강조
- **자가출판 계획용**: 저자 본인의 집필 로드맵. 일정·분량·작업 계획 중심
- **내부 검토용**: 공저·기획팀과 공유하는 내부 문서. 구조·역할 분담 중심

### 출판 기획서 구성

> **템플릿 참조:** 이 스킬 폴더 내 `publishing-proposal-template.md`를 읽고 적용한다.

기획서는 아래 섹션으로 구성한다:

1. **제목·부제** — 가제 포함 2~3안 제시
2. **저자 소개** — 이 주제에 대한 자격·경험 중심 (약력이 아닌 "왜 이 사람이 쓰는가")
3. **기획 의도** — Phase 3 콘셉트를 확장. "왜 지금 이 책이 필요한가" (300~500자)
4. **독자 대상** — Phase 2 독자 프로필 요약
5. **시장 분석** — Phase 2 유사서·차별점 요약
6. **목차** — Phase 4 목차 전문
7. **챕터별 개요 요약** — Phase 4에서 핵심 논점·소제목만 추출한 압축본
8. **예상 사양** — 총 분량(원고지/페이지), 예상 집필 기간, 판형, 특이사항
9. **마케팅 포인트** (출판사 제안용만 해당) — 타깃 채널, 저자의 기존 플랫폼·독자층, 홍보 가능 자산

### 출력 규칙

- 초안은 대화창 텍스트로 제공한다
- 사용자 확인 후 최종본을 문서 파일로 만든다. 환경에서 파일 생성이 되지 않으면 복사해 쓸 수 있는 본문으로 낸다

### Phase 5 완료 기준
- 용도에 맞는 기획서가 작성되었다
- Phase 1을 수행한 경우 선택한 아이디어가 반영되었고, Phase 2~4 결과가 빠짐없이 반영되었다
- 제목안이 2~3개 제시되었다
- 사용자가 최종 기획서를 확인·승인한다

## Phase 6: 기획 인계 블록

**목표:** Phase 1~5 결과를 후속 스킬이 읽는 단일 파일로 옮긴다. 이 단계가 없으면 book-research·book-writing-pro·book-feedback-reader가 기획 내용을 사용자에게 다시 묻는다.

출판 기획서는 사람이 읽는 문서이고, 인계 블록은 스킬이 읽는 파일이다. 용도가 다르므로 따로 만든다.

> **템플릿 참조:** 이 스킬 폴더 내 `handoff-template.md`를 읽고 적용한다.

### 슬롯 구성

| 슬롯 | 내용 | 출처 | 읽는 스킬 |
|------|------|------|----------|
| 0 | 프로젝트 기본 정보 (가제·장르·분량·종결어미·출처 표기 방식) | Phase 3·5 + 추가 확인 | 전 스킬 |
| 1 | 콘셉트 (한 문장 콘셉트·차별점·읽은 뒤 변화·쓰지 않을 것) | Phase 3 | writing-pro, feedback-reader |
| 2 | 독자 프로필 (핵심·확장 독자, 현재·기대 수준, 반복 질문) | Phase 2 | writing-pro, feedback-reader |
| 3 | 목차 | Phase 4 | writing-pro, research |
| 4 | 챕터별 개요 (핵심 논점·소제목·핵심 소재·앞뒤 연결) | Phase 4 | research, writing-pro |
| 5 | 경험 소재 요청 목록 | Phase 4 + 저자 확인 | writing-pro Phase 4 |
| 6 | 리서치 요청 목록 | Phase 4 + 저자 확인 | research Step 1 |

슬롯 번호는 후속 스킬이 참조하는 고정 번호다. 번호를 바꾸거나 슬롯을 삭제하지 않는다. 채울 내용이 없으면 `[미정]`으로 남긴다.

### 추가 확인 항목

Phase 1~5에서 다루지 않았으므로 이 단계에서 확인한다. 한 번에 하나씩 묻는다.

1. **종결어미**: `~다`체 / `~합니다`체. 장르에 맞춰 추천하되 사용자가 정한다
2. **출처 표기 방식**: 국내 실용서 / KCI / APA / Chicago / 간략형. 정하지 못하면 `[미정]`으로 두고 집필 후 확정한다

### 출력 규칙

- 파일명: `00 기획 인계.md`
- 저장 위치: 책 프로젝트 폴더
- 인계 블록은 대화창에 전문을 펼치지 않는다. 슬롯별 채움 여부와 `[미정]` 항목만 표로 보고한다
- 기존 파일이 있으면 `00 기획 인계_YYYYMMDD-HHMM.md`로 백업한 뒤 갱신한다

### Phase 6 완료 기준
- 슬롯 0~4가 채워졌다 (슬롯 5·6은 비어 있어도 된다)
- 슬롯 0의 종결어미가 확정되었다
- 슬롯 4의 챕터 수가 슬롯 3 목차의 챕터 수와 일치한다
- 파일이 프로젝트 폴더에 저장되었다

기획 완료 후 사용자에게 후속 단계를 분기 안내한다:

## 단계 간 이동 규칙

- 각 Phase는 사용자 승인 후 다음 Phase로 진행한다
- 이전 Phase로 돌아가 수정하는 것은 언제든 가능하다. 수정 시 이후 Phase에 영향이 있으면 변경 사항을 안내한다
- 사용자가 이미 준비한 자료(기존 목차, 독자 분석 등)가 있으면 해당 Phase를 건너뛴다

## 압축 모드

사용자가 "바로 기획서 만들어줘", "기획서 한 번에" 등 최종 산출물만 요청하면 압축 모드로 실행한다.

### 압축 모드 프로세스

사용자의 준비 상태에 맞는 시작 단계부터 Phase 4까지 내부에서 순차 실행하되, 사용자에게는 핵심 결정 포인트만 확인한다.

**최소 확인 항목 (사용자 입력 필수):**
1. 출발 키워드 또는 확정한 주제와 집필 동기
2. 아이디어 선택 — 주제가 확정되지 않은 경우 Phase 1 후보 3~5개 중 선택 요청
3. 콘셉트 방향 선택 — 후보 2~3안 제시 후 선택 요청 (Phase 3 산출)
4. 기획서 용도 — 출판사 제안용 / 자가출판 / 내부 검토 (Phase 5 입력)
5. 종결어미 — `~다`체 / `~합니다`체 (Phase 6 슬롯 0 입력)

**내부 처리 (사용자 확인 없이 진행):**
- 주제가 이미 확정된 경우 Phase 1을 건너뛴다
- 독자 프로필, 시장 분석, 목차, 챕터별 개요는 선택한 아이디어를 기반으로 자동 생성한다
- 독자 관점 검증(Phase 4-3)은 내부에서 실행하되, 결과를 기획서에 반영한다

**압축 모드 산출물:**
- Phase 5 출판 기획서 전문을 대화창 텍스트로 제공한다
- 기획서 앞에 "콘셉트 → 독자 → 목차" 요약(10줄 이내)을 붙여 전체 기획 과정을 보여준다
- Phase 6 인계 블록도 함께 생성한다. 압축 모드에서도 이 단계는 건너뛰지 않는다
- 사용자가 특정 Phase를 수정하고 싶으면 해당 Phase로 전환한다
