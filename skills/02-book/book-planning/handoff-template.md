# 기획 인계 블록 템플릿 (Handoff Block Template)

> book-planning Phase 6에서 프로젝트 폴더에 `00 기획 인계.md`로 생성한다.
> 이 파일 하나가 book-research·book-writing-pro·book-feedback-reader의 1순위 입력이다.
> 슬롯 번호는 후속 스킬이 참조하는 고정 번호다. 번호를 바꾸거나 슬롯을 삭제하지 않는다. 채울 내용이 없으면 `[미정]`으로 남긴다.

---

## 파일 형식

```markdown
---
프로젝트: {책 제목}
생성: YYYY-MM-DD
출처: book-planning Phase {시작}~5
---

# 기획 인계 — {책 제목}

## 슬롯 0. 프로젝트 기본 정보

| 항목 | 값 |
|------|-----|
| 가제 | {제목} |
| 장르·형식 | {실용서 / 가이드북 / 교재 / 에세이} |
| 예상 분량 | {N}장 / 원고지 {N}매 |
| 종결어미 | {~다체 / ~합니다체} |
| 출처 표기 방식 | {국내 실용서 / KCI / APA / Chicago / 간략형 / 미정} |
| 기획서 용도 | {출판사 제안 / 자가출판 / 내부 검토} |

## 슬롯 1. 콘셉트

- **한 문장 콘셉트:** {누구를 위해, 무엇을, 어떤 방식으로 다루는 책인가}
- **차별점:** {유사서 대비 이 책만의 관점·구조·접근법}
- **읽은 뒤 변화:** {책을 덮은 후 독자가 할 수 있어야 하는 것}
- **쓰지 않을 것:** {의도적으로 제외한 범위}

## 슬롯 2. 독자 프로필

| 구분 | 내용 |
|------|------|
| 핵심 독자 | {가장 좁은 정의. 페르소나 설계의 기준축} |
| 확장 독자 | {스펙트럼 바깥쪽. 페르소나 설계의 경계} |
| 현재 수준 | {독자가 이미 아는 것} |
| 기대 수준 | {읽고 나서 도달할 지점} |
| 반복 질문 | {이 독자가 자주 던지는 질문 2~3개} |

## 슬롯 3. 목차

{파트 구분 포함 전체 목차. 챕터 번호는 2자리}

## 슬롯 4. 챕터별 개요

챕터마다 아래 4항목을 채운다.

### Ch01 {챕터 제목}
- 핵심 논점:
- 소제목: {3~5개}
- 핵심 소재:
- 앞뒤 연결: {이전 장에서 이어받는 것 / 다음 장에 넘기는 것}

## 슬롯 5. 경험 소재 요청 목록

챕터별로 저자의 직접 경험이 들어가야 하는 지점을 적는다. 아직 소재가 없으면 `[소재 필요]`로 표시한다.

| Ch | 삽입 지점 | 필요한 경험 | 상태 |
|----|----------|-------------|------|
| 01 | {소제목명} | {어떤 장면이 필요한가} | [소재 필요] |

## 슬롯 6. 리서치 요청 목록

외부 자료로 근거를 보강해야 하는 지점을 적는다. book-research Step 1의 조사 방향 입력이 된다.

| Ch | 확인이 필요한 것 | 자료 유형 | 우선순위 |
|----|-----------------|----------|---------|
| 01 | {수치 / 사례 / 반론} | {공공통계 / 업계 리포트 / 논문} | 상 |
```

## 작성 규칙

- 슬롯 0의 종결어미와 출처 표기 방식은 후속 스킬이 재질문하지 않는 값이다. 확정하지 못하면 `[미정]`으로 두고, 확정 시점에 이 파일을 갱신한다.
- 슬롯 2 핵심 독자는 book-feedback-reader의 페르소나 1 기준축이 된다. "40~50대 직장인" 수준이 아니라 상황·동기까지 적는다.
- 슬롯 4는 Phase 4 챕터별 개요를 그대로 옮긴다. 요약하지 않는다.
- 슬롯 5·6은 기획 단계에서 비어 있어도 된다. 집필·리서치가 진행되며 채워진다.
- 사용자 발언과 이 파일이 충돌하면 사용자 발언이 우선한다. 이때 이 파일 갱신을 제안한다.
