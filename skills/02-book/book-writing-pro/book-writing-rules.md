# book-writing-pro 집필 규칙

SKILL.md의 Phase 3~6에서 읽는 이 스킬 고유 규칙이다.

> **참조:** `writing-principles.md`
> 문체, 금지어(①~⑦), 단어 선택, 분량 통제, AI 초안 규칙, AI 도구 표기의 상세 규칙을 포함한다. 모든 Phase에서 적용한다.

이하는 `writing-principles.md`에 없는 이 스킬 고유 규칙이다. 충돌 시 아래가 우선한다.

### 문단 기준 조정
- 문단은 **2~4문장**을 기본으로 한다 (`writing-principles.md`의 3~5문장 기준을 이 스킬에서 조정). 최대 5문장은 논리 전개가 필요한 경우에만 허용한다

### 문장 품질 기준 (GOOD/BAD 예시)

규칙보다 예시가 출력 품질에 더 큰 영향을 준다. 초안 작성 시 아래 쌍을 기준으로 삼는다.

| BAD (금지) | GOOD (기준) |
|-----------|------------|
| AI를 활용하면 쉽게 콘텐츠를 만들 수 있습니다 | AI에 원고 구조를 입력하면, 초안 생성 시간이 3시간에서 40분으로 줄어든다 |
| 혁신적인 방법으로 업무 효율을 높일 수 있습니다 | 반복 보고서 3건을 템플릿화하자, 주간 작성 시간이 절반이 됐다 |
| 이 기능은 매우 강력해서 다양한 작업에 활용할 수 있습니다 | 이 기능은 프롬프트 1개로 3가지 변형을 동시에 생성한다. 용도별로 골라 쓰면 된다 |

### 독자 프로필 적용 규칙

독자 정의는 Phase 1에서 수집하며, 수집된 독자 프로필을 전 단계에 걸쳐 적용한다. 프로젝트별 독자 프로필이 별도 파일로 존재하면 이를 참조한다.

**독자 유형별 서술 원칙:**
- **입문자**: "언제 이 기능/개념을 써야 하는가?"에 답하는 구조. 판단 기준과 반복 가능한 구조를 제공한다.
- **실무자**: 기준 → 적용 → 결과 해석 순으로 실습 예시 제시. 용도별 설계 기준과 품질 통제 방법을 제공한다.
- **기획자/강사**: 판단 기준을 문장으로 명확히 남겨 응용 가능하게. 효율적인 워크플로우와 재사용 구조를 제공한다.

### `[TODO]` 마커 유형 분류

집필 중 확인/보완이 필요한 구간에는 유형별 TODO 마커를 삽입한다. 퇴고 시 유형별로 필터링하여 우선순위를 판단한다.

| 마커 | 용도 | 예시 |
|------|------|------|
| `[TODO-FACT: ...]` | 수치·사실관계 확인 필요 | `[TODO-FACT: 해상도 기본값 확인]` |
| `[TODO-IMAGE: ...]` | 이미지·스크린샷 추가 필요 | `[TODO-IMAGE: 설정 화면 캡처 삽입]` |
| `[TODO-LINK: ...]` | 이전/이후 장 참조 확인 | `[TODO-LINK: Ch5 프롬프트 구조 참조 정확성 확인]` |
| `[TODO-EXAMPLE: ...]` | 예시·사례 보강 필요 | `[TODO-EXAMPLE: 실패 사례 추가]` |
| `[TODO-REVIEW: ...]` | 저자 판단·검토 필요 | `[TODO-REVIEW: 이 설명이 입문자에게 충분한지 확인]` |
| `[TODO-EXP: ...]` | 경험·사례 삽입 필요 | `[TODO-EXP: 이 소제목에 직접 경험 추가 필요]` |

## 원문 보존 강도 레벨

사용자의 요청 동사에 따라 보존 강도를 자동 판별한다. 레벨을 혼동하지 않는다.

| 레벨 | 트리거 | 허용 범위 | 금지 행위 |
|------|--------|----------|----------|
| **L1 교정** | "다듬어줘", "교정해줘", "수정해줘" | 맞춤법·띄어쓰기·종결어미 통일만. 문장 구조 변경 금지 | 문장 분리·병합, 새 문장 추가, 문단 재배치 |
| **L2 정리** | "정리해줘", "깔끔하게", "보강해줘" | 문장 분리·접속 보강, 지정 부분 내용 추가. 미지정 부분 원본 유지 | 구조 재배치, 슬롯 순서 변경, 미지정 부분 수정 |
| **L3 리라이팅** | "리라이팅해줘", "다시 써줘" | 구조 재배치·문장 교체·패턴 적용 허용 | 분량 120% 초과 (초과 시 사유 확인) |

- 사용자가 레벨을 명시하지 않으면 트리거 동사로 자동 판별한다
- 초안 작성 시 사용자가 분량을 지정하지 않으면, 소제목당 2~3문단을 기본값으로 한다

## 실무 정리 블록 구성

각 챕터 말미에 다음 중 적합한 항목을 포함:
- **적용 체크리스트**: 이 챕터에서 배운 내용을 실무에 적용할 때의 점검 항목
- **자주 발생하는 실수**: 독자가 흔히 빠지는 함정과 대처법
- **구조 예시**: 프롬프트, 워크플로우, 판단 흐름도 등

## 형식 및 가독성

- 번호 목록, 단계 박스, 비교 표 적극 활용
- 텍스트가 주가 되며, 이미지는 설명 보조 역할
- 모든 이미지/예시에는 **"왜 이것을 예시로 썼는지"** 설명 필수
- 이미지 캡션: 감상평 금지, 기능·의도·판단 기준 중심

## 장 간 일관성·반복 방지

다수 챕터에 걸쳐 용어, 개념 설명, 난이도가 흔들리지 않도록 다음 규칙을 적용한다.

**용어 일관성:**
- 동일 개념에 대해 장마다 다른 용어를 사용하지 않는다 (예: "프롬프트 구조"와 "명령어 체계"를 혼용하지 않음)
- 새 용어가 등장하면 최초 1회 정의하고, 이후 장에서는 정의 없이 사용한다
- 용어 정의가 필요할 때는 이전 장에서 사용한 표현을 그대로 따른다
- **작가 관점 선언의 glossary(반복 키워드·개념 정의)를 기준으로 한다**

**반복 방지:**
- 챕터 작성 전, 이전 장에서 이미 설명한 개념인지 확인한다
- 이미 설명한 개념을 다시 다뤄야 할 경우: 재설명하지 않고 **"N장에서 다룬 [개념명]을 기준으로"** 형태로 참조한다
- 같은 파트(Part) 내에서 동일한 판단 기준이나 원칙을 두 번 이상 풀어 설명하지 않는다

**난이도 관리:**
- 파트 순서에 따라 난이도가 자연스럽게 상승한다. 뒤 파트에서 앞 파트 수준의 기초 설명을 반복하지 않는다
- 파트 내 첫 장은 해당 파트의 핵심 개념을 도입하고, 이후 장들은 이를 전제로 전개한다

## "Claude 판단에 맡김" 위치 선정 기준

삽입 위치를 사용자가 지정하지 않을 경우, 다음 기준으로 위치를 결정한다:

| 경험 유형 | 기본 배치 위치 | 이유 |
|-----------|--------------|------|
| 직접경험 | 판단 기준 제시 직후 | 기준의 실제 근거로 기능 |
| 관찰사례 | 문제 상황 제시 직후 (소제목 도입부) | 독자 공감 유도, "이런 경우를 봤다" |
| 실패담 | "왜 흔들리는가" 설명과 기준 재정의 사이 | 기존 방식의 한계를 체감시킴 |
| 비교사례 | 방법론 비교 또는 선택 기준 제시 구간 | 조건별 결과 차이를 보여줌 |
| 전환점 | 장 도입부 또는 관점 전환 마무리 | 사고 전환의 계기로 기능 |

- 한 소제목 안에 경험이 2개 이상 들어가면 논리 흐름이 끊긴다. **소제목당 경험 1개를 기본**으로 한다.
- 배치 후 앞뒤 문단과의 연결이 자연스러운지 반드시 확인한다.
