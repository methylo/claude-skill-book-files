# 책 삽화 프롬프트 설계 워크플로우 (Book Illustration Prompt Workflow)

원고(또는 목차)에서 출발하여 챕터별 AI 이미지 생성 도구용 구조화된 삽화 프롬프트를 만드는 5단계 프로세스.

## 보조 파일 구조

| 파일 | 내용 | 참조 시점 |
|------|------|---------|
| `composition-guide.md` | 구도 설계 가이드 (라인 3종 + 인포 6종, 전환 장치, 선택 기준) | Step 2~3 |
| `line-drawing-prompts.md` | 라인 드로잉 마스터 프롬프트 3종 + 스타일 규칙 | Step 4 |
| `infographic-prompts.md` | 인포그래픽 마스터 프롬프트 4종 + 스타일 규칙 | Step 4 |
| `color-system.md` | 색상 체계 + 장르별 기본 색상 세트 | Step 5 |

**작업 시작 전**: 해당 Step에 필요한 보조 파일을 반드시 읽는다.

---

## 전체 흐름

```
Step 1: 원고 분석·챕터 분류 (Analyze)
  → Step 2: 유형 판단 (Classify)          ← composition-guide.md 참조
    → Step 3: 구도 설계 (Compose)          ← composition-guide.md 참조
      → Step 4: 프롬프트 구조화 (Build)    ← line-drawing-prompts.md / infographic-prompts.md 참조
        → Step 5: 일관성 점검 (Unify)      ← color-system.md 참조
```

사용자의 상태에 따라 적절한 단계부터 시작한다.

| 상태 | 진입 |
|------|------|
| 원고 파일 제공 | Step 1부터 |
| 목차·챕터 구조만 있음 | Step 1부터 (축약) |
| 유형(라인/인포)이 이미 정해짐 | Step 3부터 |
| 특정 챕터 1개만 요청 | Step 2~4 (해당 챕터만) |
| 기존 프롬프트 수정 | Step 4 (수정) |
| 전체 배치 계획만 요청 | Step 5 |

### Step 간 전환 규칙

| 전환 | 확인 방식 |
|------|----------|
| Step 1 → 2 | 챕터별 핵심 개념 추출 결과를 제시하고 확인 |
| Step 2 → 3 | 유형 분류표(라인/인포)를 제시하고 확인 |
| Step 3 → 4 | 구도 설계(좌·중앙·우 구성)를 제시하고 확인 |
| Step 4 → 5 | 완성된 프롬프트를 제시하고 확인 |

사용자가 "전체 한 번에 해줘"라고 요청한 경우, Step 1~5까지 연속 진행한다.

## 핵심 판단 기준: 라인 드로잉 vs 인포그래픽

이 스킬의 핵심은 **원고를 읽고 각 챕터를 2가지 유형 중 하나로 분류하는 것**이다.

| 판단 기준 | 라인 드로잉 | 인포그래픽 |
|----------|-----------|----------|
| 챕터 성격 | 장면·경험·감정 중심 | 구조·프로세스·비교 중심 |
| 핵심 전달 | "이런 상황이었다" | "이런 구조다" |
| 독자 반응 | 공감·몰입 | 이해·정리 |
| 원고 단서 | 시간·장소·행동이 나오는 서사 | 표, Before/After, 단계, 항목 나열 |

### 원고에서 유형을 판단하는 방법

1. **서사 단서 확인**: 챕터 첫 1~3문단에 시간·장소·행동·감정이 등장하면 → 라인 드로잉
2. **구조 단서 확인**: 챕터에 Before/After, 표, 단계별 나열, 비교 구조가 있으면 → 인포그래픽
3. **둘 다 있는 경우**: 챕터의 결론부가 "감상/깨달음"이면 라인 드로잉, "체계/기준"이면 인포그래픽
4. **한 권에서 두 유형을 섞을 수 있다**: 서사 파트는 라인 드로잉, 체계 파트는 인포그래픽

## Step 1: 원고 분석·챕터 분류 (Analyze)

### 목적
원고를 읽고 각 챕터의 핵심 개념과 시각화 가능 요소를 추출한다.

### 추출 항목 (챕터당)

| 항목 | 추출 방법 |
|------|---------|
| 챕터 제목 | 목차에서 추출 |
| 핵심 개념 | 챕터의 1문장 요약 — "이 챕터는 ___를 말한다" |
| 시각화 포인트 | 시각으로 전달하면 텍스트보다 효과적인 요소 1개 |
| 원고 단서 | 장면 서사인가, 구조 설명인가 — 판단 근거 문장 인용 |
| 파트 위치 | 전체 구조에서의 위치 (도입/전개/전환/결론) |

### 추출 방법

1. **원고 파일이 제공된 경우**: 각 챕터의 첫 3문단 + 마지막 2문단을 읽고 핵심 추출
2. **목차만 제공된 경우**: 챕터 제목에서 성격을 추론하고, 사용자에게 보완 질문
3. **아무것도 없는 경우**: 책 제목·장르·목차를 먼저 요청

### 출력 형식

```markdown
## Step 1 결과: 원고 분석

### 책 정보
- 제목: {제목}
- 장르: {장르}
- 전체 구조: {Part/챕터 수}

### 챕터별 핵심 추출

| 챕터 | 핵심 개념 | 시각화 포인트 | 원고 단서 | 유형 후보 |
|------|---------|------------|---------|---------|
| Ch 1 | ... | ... | 장면 서사 / 구조 설명 | 라인/인포 |
| Ch 2 | ... | ... | ... | ... |
| ... | ... | ... | ... | ... |
```

## Step 2: 유형 판단 (Classify)

> **참조**: `composition-guide.md` — 인포그래픽 세부 유형 6가지 정의

### 목적
Step 1의 결과를 바탕으로 각 챕터를 라인 드로잉 또는 인포그래픽으로 확정한다.

### 인포그래픽 세부 유형

인포그래픽으로 분류된 챕터는 6가지 세부 유형(비교형, 프로세스형, 계층형, 타임라인형, 구조형, 순환형) 중 하나를 추가 지정한다.
각 유형의 정의·적합 조건·선택 결정 트리는 `composition-guide.md`를 참조한다.

### 출력 형식

```markdown
## Step 2 결과: 유형 판단

| 챕터 | 유형 | 세부 유형 | 판단 근거 |
|------|------|---------|---------|
| Ch 1 | 라인 드로잉 | — | 첫 문단이 장면 서사 |
| Ch 2 | 인포그래픽 | 비교형 | Before/After 구조 존재 |
| ... | ... | ... | ... |

### 요약
- 라인 드로잉: {N}장
- 인포그래픽: {N}장
- 총: {N}장
```

## Step 3: 구도 설계 (Compose)

> **참조**: `composition-guide.md` — 구도 선택 기준, 전환 장치, 상세 규칙 전체

### 목적
각 챕터의 유형에 맞는 구도를 설계한다. 구도 선택 기준과 상세 규칙은 `composition-guide.md`를 따른다.

### 출력 형식

```markdown
## Step 3 결과: 구도 설계

### Ch {N}: {챕터 제목}
- 유형: {라인 드로잉 / 인포그래픽}
- 구도: {좌우 대칭 / 중앙 집중 / 시간 흐름 / 비교형 / 프로세스형 / 타임라인형 / 구조형 / 계층형 / 순환형}

#### 좌우 대칭·비교형·프로세스형·타임라인형·구조형인 경우:
- 좌측: {설명}
- 중앙: {전환 장치}
- 우측: {설명}

#### 중앙 집중형인 경우:
- 중앙 인물: {설명}
- 주변 요소: {방사형 배치 요소 나열}

#### 시간 흐름형인 경우:
- 장면 1: {설명}
- 장면 2: {설명}
- 장면 3: {설명}
- 장면 연결: {전환 장치}

#### 계층형인 경우:
- 하단(기반): {설명}
- 구분선: {장치}
- 상단(표면): {설명}

#### 순환형인 경우:
- 좌상(1단계): {설명}
- 우상(2단계): {설명}
- 우하(3단계): {설명}
- 좌하(4단계): {설명}
- 중앙: {핵심 아이콘}

- 인물/요소 상태 변화: {Before} → {After}
```

## Step 4: 프롬프트 구조화 (Build)

> **참조**: 유형에 따라 해당 파일을 읽는다.
> - 라인 드로잉 → `line-drawing-prompts.md`
> - 인포그래픽 → `infographic-prompts.md`

### 목적
구도 설계를 바탕으로 AI 이미지 생성 도구에 입력할 구조화된 프롬프트를 작성한다.

### 프롬프트 작성 시 3섹션 원칙

각 챕터의 프롬프트는 다음 3개 섹션으로 설명한 뒤, 마지막에 프롬프트 텍스트를 생성한다.

**① 기본 설명**: 챕터 핵심, 시각화 포인트, 인물 상태 변화(라인) 또는 유형 선택 근거(인포)
**② 구도 상세**: 구도 유형에 따른 각 영역의 구체적 구성 요소 상세 기술
**③ 기타**: 분위기, 핵심 차이, 소품 표현 방법, 주의사항

### 마스터 프롬프트 선택

| 유형 | 구도 | 사용할 프롬프트 | 파일 |
|------|------|-------------|------|
| 라인 드로잉 | 좌우 대칭 | 기본 마스터 프롬프트 | `line-drawing-prompts.md` |
| 라인 드로잉 | 중앙 집중 | 중앙 집중형 프롬프트 | `line-drawing-prompts.md` |
| 라인 드로잉 | 시간 흐름 | 시간 흐름형 프롬프트 | `line-drawing-prompts.md` |
| 인포그래픽 | 비교/프로세스/타임라인/구조 | 기본 마스터 프롬프트 | `infographic-prompts.md` |
| 인포그래픽 | 순환형 | 순환형 전용 프롬프트 | `infographic-prompts.md` |
| 인포그래픽 | 계층형 | 계층형 전용 프롬프트 | `infographic-prompts.md` |

## Step 5: 일관성 점검·배치 계획 (Unify)

> **참조**: `color-system.md` — 장르별 색상 세트, 파트별 보조색 체계

### 목적
전체 챕터의 삽화를 시리즈로 통일하고, 제작 순서와 파트별 색감을 확정한다.

### 일관성 유지 3가지 규칙

**1. 스타일 고정**
- 라인 드로잉: 첫 번째 삽화의 [스타일] 항목을 전체 챕터에 복사·재사용
- 인포그래픽: 도형 스타일(둥근 모서리, 아이콘 세트)을 전체 통일

**2. 색감 고정**
- 라인 드로잉: 흑백 통일 (파트별 보조색 적용하지 않음)
- 인포그래픽: 주조색 고정 + 파트별 보조색만 변경 (`color-system.md` 참조)

**3. 캐릭터/아이콘 고정**
- 라인 드로잉: 스틱 피겨의 비율·선 굵기·머리 크기를 첫 회에 정하고 반복
- 인포그래픽: 아이콘 세트(사람, AI, 문서, 체크 등)를 첫 회에 정하고 반복

### 배치 계획표

전체 삽화를 한눈에 관리하는 표를 생성한다.

```markdown
## 전체 삽화 배치 계획표

| 챕터 | 유형 | 세부 유형/구도 | 영역 A | 영역 B | 보조색 |
|------|------|-----------|--------|--------|-------|
| Ch 1 | 라인 드로잉 | 좌우 대칭 | 좌측: ... | 우측: ... | — |
| Ch 2 | 인포그래픽 | 비교형 | 좌측: ... | 우측: ... | #XXXXXX |
| Ch 3 | 라인 드로잉 | 중앙 집중 | 중앙 인물: ... | 주변 요소: ... | — |
| Ch 4 | 인포그래픽 | 순환형 | 1~2단계: ... | 3~4단계: ... | #XXXXXX |
| Ch 5 | 인포그래픽 | 계층형 | 하단(기반): ... | 상단(표면): ... | #XXXXXX |
| Ch 6 | 라인 드로잉 | 시간 흐름 | 장면1~2: ... | 장면3: ... | — |
| ... | ... | ... | ... | ... | ... |
```

**영역 A·B 해석**: 구도에 따라 영역의 의미가 달라진다. 칼럼 안에 "좌측:", "하단:", "중앙 인물:" 등 라벨을 포함하여 혼동을 방지한다.

### 최종 체크리스트

| 체크 | 질문 |
|------|------|
| 스타일 통일 | 라인 드로잉의 선 굵기·인물 비율이 전체 동일한가? |
| 색감 통일 | 인포그래픽의 주조색이 전체 동일한가? 파트별 보조색이 일관적인가? |
| 구도 적합성 | 각 챕터의 원고 성격에 맞는 구도인가? (억지 좌우 대칭은 아닌가?) |
| 정보 정확성 | 프롬프트의 장면/구조 설명이 원고 내용과 일치하는가? |
| 텍스트 최소화 | 텍스트가 핵심 키워드만 최소한으로 포함되어 있는가? 불필요한 문장이 없는가? |
| 비율 통일 | 모든 프롬프트의 비율(16:9 또는 1:1 등)이 통일되어 있는가? |

## 공통 출력 조건

모든 삽화 프롬프트에 아래를 포함한다.

```
[공통 조건]
- 배경: 흰색(#FFFFFF) 단색
- 텍스트: 필요 시 핵심 키워드 포함 가능 (한국어+영문 병기, 최소한으로)
- 비율: 가로형(16:9)
- 해상도: 고해상도
- 시리즈 전체 동일 스타일 유지
[출처] 본 이미지는 나노바나나의 AI 이미지 생성 기능을 활용하여 제작되었습니다.
```

## 출력 매체 규칙

| 산출물 | 출력 방식 |
|--------|---------|
| Step 1~4 각 단계 결과 | 대화창 텍스트로 제공 |
| 개별 챕터 프롬프트 | 대화창 텍스트 (코드 블록으로 감싸서 복사 가능하게) |

## AI 이미지 생성 시 주의사항

1. **텍스트는 최소한으로** — AI 한글 렌더링이 부정확할 수 있으므로 핵심 키워드만 포함. 세부 텍스트는 Canva/Keynote에서 별도 배치
2. **축약 버전으로 먼저 테스트** — 풀 프롬프트 투입 전에 방향 확인
3. **3~5장 생성 후 1장 선별** — 1장만 생성하지 않음
4. **프롬프트 수정은 섹션 단위** — 전체 재작성 아님, [좌측] 또는 [기타]만 변경
5. **스타일 통일은 첫 장이 기준** — 첫 삽화가 마음에 들면 그 프롬프트의 [기본]을 전체에 복사
