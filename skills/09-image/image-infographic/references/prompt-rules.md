# 프롬프트 작성·점검 규칙

프롬프트 문장 원칙, 길이, 수정 대응, 자가 점검(Harness) 기준이다.

## 프롬프트 작성 원칙

1. **첫 문장에 유형+스타일 필수**: `[유형] [스타일] 인포그래픽 이미지를 생성해줘.` 형식으로 시작
2. **한국어로 작성**: 프롬프트 전체를 한국어로
3. **비율로 사이즈 지정**: `16:9` 기본, 필요시 변경
4. **텍스트 기준**: 통합표 참조 (제목 12자, 키워드 8자, 부가 설명 15자, 항목 6개 이내)
5. **색상 명시**: 주색은 헥스코드, 보조색은 팔레트 참조
6. **구도 중심 지시**: 배치 방향·위치를 명확히, 세밀한 수치는 지양
7. **시각 스타일 블록 필수**: 모든 프롬프트 하단에 공통 스타일 포함
8. **시각 밀도 확보**: 아래 밀도 보강 규칙을 반드시 적용

**지시 수준 가이드**: 구도·색상·배치 방향 수준으로 지시한다. CSS 수준의 수치는 피한다.

| 적절한 지시 | 피해야 할 지시 |
|-------------|---------------|
| "가로로 균등 배치" | "카드 간 8px 간격" |
| "둥근 모서리 카드" | "border-radius: 12px" |
| "연한 파랑 배경" | "#E3F2FD, opacity 0.8" |
| "굵은 화살표로 연결" | "화살표 두께 3px" |

## 프롬프트 길이 가이드라인

나노바나나 프로는 프롬프트가 길어도 비교적 잘 처리하지만, 다음 기준을 지킨다.

| 항목 수 | 적정 프롬프트 줄 수 | 주의사항 |
|---------|-------------------|---------|
| 3개 | 25~30줄 | 가장 안정적 |
| 4개 | 30~40줄 | 권장 범위 |
| 5~6개 | 40~50줄 | 부가 설명·하위 태그를 1~2개로 축소 |
| 7개 이상 | 생성하지 않음 | 항목을 6개 이하로 줄이거나 2장으로 분리 |

**핵심 원칙**: 항목이 늘어날수록 카드당 정보량(부가 설명·하위 태그)을 줄여 전체 프롬프트 밀도를 조절한다. 장면형은 동작 묘사가 길어지므로 항목 4개 이하를 권장한다.

## 수정·변환 대응

- **스타일 전환**: 같은 원고를 다른 스타일로 재구성
- **항목 추가/삭제**: 원고에서 추출한 포인트 수 조정
- **색상 변경**: 헥스코드 또는 색상명 교체 (팔레트 참조)
- **유형 전환**: 같은 원고를 다른 유형으로 재구성
- **캐릭터 추가/제거**: 스틱맨 포함 여부
- **장면 수정**: 스틱맨 동작·소품·표정 변경
- **비율 변경**: 16:9 → 4:3, 1:1, 9:16 등
- **한글 오류 수정**: "이미지에서 OOO를 OOO로 수정해줘" 후속 프롬프트 안내
- **원고 재입력**: 다른 단락을 넣어 새 슬라이드 프롬프트 생성

수정 시 전체 프롬프트를 다시 코드블록으로 출력한다.

## Harness 블록

이 스킬의 하네스 파라미터는 다음과 같다.

| 항목 | 값 |
|------|-----|
| **원문 보존 레벨** | L1 (요약형) — 원고를 슬라이드 1장 분량으로 압축, 핵심 메시지만 살림 |
| **생성-평가 분리** | Step 2 핵심 추출 → Step 4 프롬프트 작성 → 자가 평가 루프 → Step 5 출력 |
| **분량 가드레일** | 프롬프트 400~800자 (기본), 배치 생성 시 슬라이드당 동일 범위 유지 |
| **재생성 트리거** | 자가 평가 실패 시 Step 2 핵심 추출부터 다시 실행 |

### 자가 평가 루프 (프롬프트 출력 전 반드시 실행)

**1. 원고 핵심 왜곡 점검 (L1 요약형 핵심)**
- [ ] 원고의 **핵심 메시지 1개**가 프롬프트에 반영되었는가
- [ ] 원고에 없는 사실·사례·숫자를 임의로 추가하지 않았는가
- [ ] 원고의 논조·입장이 왜곡되지 않았는가 (긍정을 부정으로, 비판을 옹호로 바꾸지 않음)

**2. 프롬프트 명료성 점검**
- [ ] 유형(요약형/구조형/프로세스형)이 원고 성격과 일치하는가
- [ ] 레이아웃(L1~L5)이 원고 성격과 일치하는가
- [ ] 배경·폰트·캐릭터 기본값(#FFFFFF, Noto Sans KR, 스틱맨)이 포함되었는가
- [ ] 업체 컬러 키(메인·보조 헥스코드)가 프롬프트에 명시되었는가
- [ ] 한국어로 작성되었는가
- [ ] 텍스트 요소가 3~7개 범위 내에 있는가 (과밀·과소 방지)

**3. 시각 장치 점검**
- [ ] 원고 신호에 맞는 시각 장치(강조 배지·연결선·데이터 표시)가 선택되었는가
- [ ] 시각 장치가 2개 이하로 조합되었는가 (과다 적용 방지)
- [ ] 데이터 표시 장치 선택 시 원고에 실제 숫자가 있는가

**4. 배치 생성 시 일관성 점검 (lecture-slides 04-image-list.md 연계 시)**
- [ ] 모든 슬라이드 프롬프트가 동일한 업체 컬러 키를 사용하는가
- [ ] 같은 레이아웃이 연속 3회 반복되지 않는가
- [ ] 슬라이드 번호·파일명이 lecture-slides 출력과 일치하는가
- [ ] 출력 모드(기본/프리미엄)가 전체 배치에 일관 적용되는가

**5. 텍스트 렌더링 누출 점검 (가장 중요)**
- [ ] 프롬프트에 매거진 헤더("ISSUE 01" 형식)가 포함되지 않았는가
- [ ] 프롬프트에 영문 부제(메인 타이틀 아래 영문)가 포함되지 않았는가
- [ ] 프롬프트에 카드 내 영문 서브타이틀("Plan", "Research" 등)이 포함되지 않았는가
- [ ] "이미지에 표시할 한글 텍스트" 섹션과 "디자인 사양" 섹션이 명확히 분리되었는가
- [ ] 콘텐츠 섹션에 디자인 사양(폰트 크기·색상 코드·픽셀 수치)이 섞여 있지 않은가
- [ ] 디자인 사양 섹션에 "큰", "작은", "얇은" 등 상대적 표현 위주로 작성되었는가
- [ ] 픽셀 수치(60px, 100px 등)·헥스코드·폰트 사양이 콘텐츠 텍스트로 노출되지 않는가
- [ ] CRITICAL RENDERING RULES 영문 강제 규칙이 프롬프트 마지막에 포함되었는가

**6. 디자인 격조 점검**
- [ ] 카드 내부 6단 구조(인덱스→한글타이틀→구분선→일러스트→캡션→푸터)가 모두 포함되었는가
- [ ] 일러스트 뒤 옅은 원형 배경(업체 컬러 키 매칭)이 명시되었는가
- [ ] 카드 하단 푸터 라인이 포함되었는가
- [ ] 모든 카드의 일러스트 시각 밀도가 통일되었는가 (스틱맨 1명 + 보조 요소 2~3개)
- [ ] 필수 영문 스타일 키워드가 포함되었는가

**7. 타이틀 배치 점검 (모드별)**
- [ ] 기본 모드: T1 상단 중앙형으로 배치되었는가
- [ ] 프리미엄 모드 + 사용자 지정: 지정된 배치(T1·T2·T3)가 반영되었는가
- [ ] 프리미엄 모드 + 미지정: T2 좌측 분할형으로 기본 적용되었는가

### 원문 보존 원칙 (L1 요약형)

- 원고 → 슬라이드 1장 변환 시 **압축률 80% 이상** 허용
- 단, 핵심 메시지·고유명사·수치는 그대로 유지
- 원고에 없는 내용을 프롬프트에 추가하지 않는다 (예: "실제 사례 추가"로 허구 생성 금지)
- 프롬프트 내 텍스트 요소(제목·부제·캡션)는 원고의 표현을 직접 사용하거나 최소 수정
