# 에세이 글쓰기 워크플로우 (Essay Writing Workflow)

에세이를 위한 5단계 구조적 글쓰기 프로세스. 에세이는 논증이 아니라 **시선**으로 작동한다. 무엇을 주장할지가 아니라, 어떤 시선으로 대상을 보는지가 글의 출발점이다. 같은 경험도 시선이 다르면 다른 글이 된다.

## 칼럼과 에세이의 차이 (이 스킬의 전제)

| 구분 | 칼럼(write-content) | 에세이(이 스킬) |
|------|---------------------|----------------|
| 출발점 | 주장·논지 | 시선·태도 |
| 작동 방식 | 근거로 설득 | 시선으로 발견하게 함 |
| 구조 | 도입-전환-기준-마무리(논증) | 진입-전개-전환-여운(서사·사색) |
| 독자 반응 목표 | "맞는 말이다" (납득) | "그렇게 볼 수도 있구나" (공명) |
| 마무리 | 관점 재정렬 | 여운·열린 질문 |

논증 구조를 에세이에 강제하면 글이 칼럼이 된다. 이 스킬은 논증을 만들지 않는다.

## 보조 파일 안내

이 스킬은 워크플로우 흐름을 제공하며, 상세 규칙은 보조 파일에서 참조한다.

| 보조 파일 | 내용 | 참조 시점 |
|----------|------|----------|
| `references/gaze-design.md` | 시선 설계 상세 — 시선 4축, 시선 유형 6종, 시선 점검법 | Step 2 시선 설계 시 |
| `references/essay-style.md` | 에세이 문체 — 1인칭 화법, 감각 묘사, 문장 호흡, 절제 규칙 | Step 3 초안 작성 전, Step 4 스타일 점검 시 |
| `references/writing-principles.md` | 공통 집필 원칙, 금지어 규칙, 분량 통제(L1/L2/L3) | Step 3 초안 작성 전, Step 4 리라이팅 전 |
| `references/review-checklist.md` | Step 4 점검 1~4 상세 체크리스트 | Step 4 리라이팅 시 |
| `references/output-rules.md` | 단계별 산출물 명세, 파일명·포맷 규칙 | 각 Step 산출물 작성 시 |

**읽기 규칙:** 각 Step 진입 시 해당 보조 파일을 읽는다. 이미 같은 대화에서 읽은 파일은 다시 읽지 않는다.

## 전체 흐름

```
Step 1: 주제 탐색 → Step 2: 시선 설계 → Step 3: 초안 작성 → Step 4: 리라이팅 → Step 5: 최종 출력
```

사용자의 상태에 따라 적절한 단계부터 시작한다.
- 막연한 소재·감정만 있음 → Step 1부터
- 주제는 정해짐, 어떻게 볼지 미정 → Step 2부터
- 시선·구조 정해짐 → Step 3부터
- 초안 있음 → Step 4부터

### Step 간 전환 규칙

각 Step 완료 후, 다음 Step으로 넘어가기 전에 사용자 확인을 받는다.

| 전환 | 확인 방식 |
|------|----------|
| Step 1 → 2 | 핵심 소재·정서·쓰려는 이유를 요약 제시 → 확정 여부 확인 |
| Step 2 → 3 | 시선 설계안(시선 한 문장 + 구조 골격) 제시 → 동의 여부 확인 |
| Step 3 → 4 | 초안 제시 → 방향 수정·추가 요청 확인 |
| Step 4 → 5 | 수정본 제시 → 추가 수정 여부 확인 |

"끝까지 진행해줘" 또는 "한 번에 해줘" 요청 시 확인 없이 연속 진행한다.

## Step 1: 주제 탐색 (Subject Exploration)

에세이는 주제가 분명하지 않은 상태에서 출발하는 경우가 많다. 이 단계는 "무엇에 대해 쓸지"가 아니라 "왜 이것이 마음에 남았는지"를 찾는다.

### 수집 항목

| 항목 | 질문 |
|------|------|
| **소재** | 무엇을 쓰려고 하는가? (장면·사건·사물·인물·감정) |
| **정서** | 그 소재를 떠올릴 때 어떤 감정·상태가 따라오는가? |
| **쓰려는 이유** | 왜 지금 이것을 글로 쓰고 싶은가? |
| **분량·채널** | 짧은 단상 / 일반 에세이 / 긴 산문 중 어느 쪽인가? |

### 필수 입력 강제 규칙

아래 2개가 확인되지 않으면 Step 2로 넘어가지 않는다. 추측으로 채우지 않고 질문한다.

| 필수 항목 | 누락 시 질문 |
|----------|-------------|
| **소재** | "어떤 장면이나 경험, 또는 무엇에 대해 쓰고 싶으신가요?" |
| **쓰려는 이유** | "그 소재가 왜 지금 마음에 남았나요? 어떤 점이 계속 떠오르나요?" |

정서는 사용자가 명확히 말하지 못하면 소재 묘사에서 함께 추출한다. 채널·분량은 누락 시 "일반 에세이(1,500~2,500자)"로 기본 적용한다.

### 소재 구체화 규칙

소재가 추상적이면("외로움에 대해", "시간에 대해") 구체적 장면으로 좁힌다. 추상 개념을 직접 다루는 에세이는 설교가 되기 쉽다.

| 추상 소재 | 좁히기 질문 | 구체 소재 예 |
|----------|------------|-------------|
| 외로움 | "외로움을 느꼈던 특정 순간이 있나요?" | 텅 빈 사무실에 혼자 남은 저녁 |
| 시간 | "시간이 다르게 느껴진 장면이 있나요?" | 오래된 노트를 다시 펼친 순간 |
| 변화 | "변화를 체감한 구체적 사물·공간이 있나요?" | 이사하며 버린 책상 |

### 산출물

소재·정서·쓰려는 이유·분량을 요약 정리해 제시. 확인 후 Step 2로. (산출물 형식 상세는 `references/output-rules.md` 참조)

## Step 2: 시선 설계 (Gaze Design)

> **이 단계 진입 시** `references/gaze-design.md`를 읽는다.

이 스킬의 핵심 단계다. 같은 소재라도 어떤 시선으로 보느냐에 따라 글이 완전히 달라진다. 시선을 정하지 않고 초안을 쓰면 소재 나열에 그친다.

### 시선이란

시선은 소재를 바라보는 **각도·거리·태도**다. "이 경험을 어떤 위치에서, 무엇에 초점을 맞춰, 어떤 태도로 볼 것인가"를 결정한다. 시선이 정해지면 무엇을 쓰고 무엇을 버릴지가 결정된다.

### 시선 설계 3단계

1. **시선 축 결정** — 시선 4축(거리 / 시간 / 초점 / 태도) 중 이 글을 끌고 갈 주 축을 정한다. 상세는 `references/gaze-design.md` 참조.
2. **시선 한 문장 작성** — 이 글의 시선을 한 문장으로 고정한다. 예: "버린 책상을 통해, 무언가를 버릴 때 함께 버려지는 시간을 본다."
3. **시선 유형 매칭** — 시선 유형 6종(관찰자 / 회고자 / 질문자 / 대조자 / 동행자 / 발견자) 중 하나를 주 시선으로 선택한다. 상세는 `references/gaze-design.md` 참조.

### 시선 점검 (다음 단계 진입 조건)

시선 한 문장이 아래를 통과해야 Step 3으로 넘어간다.

- [ ] 소재(무엇)와 시선(어떻게 볼지)이 모두 들어 있는가
- [ ] "그래서 어떻게 하라"는 결론·교훈이 들어 있지 않은가 (교훈이 들어 있으면 칼럼이다)
- [ ] 한 문장으로 다른 사람에게 설명했을 때, 글의 방향이 그려지는가

### 구조 골격 설계

시선이 정해지면 구조를 짠다. 에세이는 고정 구조가 없으나, 시선을 풀어내는 기본 골격은 다음을 따른다.

```
[진입] 구체적 장면·감각으로 들어간다 (설명 아닌 묘사로 시작)
[전개] 시선을 따라 장면을 펼친다 (소재의 결을 보여줌)
[전환] 시선이 한 번 꺾인다 (다르게 보이는 지점 / 의외의 연결)
[여운] 결론 대신 여운을 남긴다 (열린 질문 / 잔상 / 작은 발견)
```

이 골격은 강제가 아니다. 시선 유형에 따라 진입과 전환의 비중이 달라진다. 유형별 구조 변형은 `references/gaze-design.md` 참조.

### 산출물

시선 한 문장 + 시선 유형 + 구조 골격을 사용자에게 제시. 동의 후 Step 3으로.

## Step 3: 초안 작성 (First Draft)

> **이 단계 진입 시** `references/essay-style.md`와 `references/writing-principles.md`를 읽는다.

### 초안 작성 모드 판별

| 입력 상태 | 모드 | 설명 |
|----------|------|------|
| 소재·시선만 있음 | **새로 쓰기 모드** | 시선 한 문장과 구조 골격을 기반으로 산문을 새로 쓴다 |
| 메모·일기·단편 텍스트 제공 | **원문 보존 모드** | 원문의 어투·감정·장면을 유지하고, 시선에 맞춰 정리·보강만 한다 |

메모 분량이 3문장 이상이면 원문 보존 모드를 기본 적용한다. 보존 강도(L1/L2/L3) 판별은 `references/writing-principles.md` 참조.

### 출력 슬롯 템플릿 (초안은 이 골격을 따른다)

Step 2에서 확정한 구조 골격을 슬롯으로 적용한다. 단, 칼럼형 슬롯과 달리 슬롯 간 경계는 부드럽게 잇는다. 소제목으로 슬롯을 끊지 않는다(긴 산문에서 사용자가 요청한 경우 제외).

```
[진입] ← 구체적 장면·감각 (설명·요약 금지, 묘사로 시작)
[전개] ← 시선을 따라 장면을 펼침 (감각 디테일, 1인칭 경험)
[전환] ← 시선이 꺾이는 지점 (다르게 보임 / 의외의 연결)
[여운] ← 결론 아님. 열린 질문·잔상·작은 발견으로 마무리
```

### 에세이 초안 작성 규칙

상세는 `references/essay-style.md`. 핵심만 옮기면 다음과 같다.

1. **첫 문장은 장면으로 연다.** 주제 선언·배경 설명으로 시작하지 않는다. (❌ "오늘은 시간에 대해 쓰려 한다" → ✅ "노트의 첫 장은 3년 전 날짜였다.")
2. **설명하지 말고 보여준다.** 감정을 단어로 말하지 않고 장면으로 드러낸다. (❌ "나는 외로웠다" → ✅ "불 꺼진 사무실에서 모니터만 혼자 깜빡였다.")
3. **1인칭 경험으로 진입한다.** 일반론·3인칭 관찰로 시작하지 않는다.
4. **여운으로 닫는다.** 마지막 문장은 요약·교훈이 아니라 잔상·질문·작은 발견이다.

### 금지어 실시간 체크

문장 생성 시 즉시 점검(상세는 `references/writing-principles.md`).
1. "~할 수 있습니다" → 단정형 또는 묘사형으로 전환
2. "매우", "쉽게", "빠르게" → 감각·장면으로 교체
3. 근거 없는 형용사 → 구체적 묘사로 대체
4. 추상 명사 중심 문장 → 장면·동작 중심으로 전환

### 에세이 특화 금지 (논증 침투 차단)

에세이가 칼럼으로 변질되는 신호. 발견 즉시 수정한다.
- "결국 중요한 것은 ~이다" 식의 교훈 선언
- "우리는 ~해야 한다" 식의 당위 명령
- "3가지 이유는" 식의 논증 나열
- 마무리에서 독자에게 행동을 요구하는 문장

### 초안 자가 점검 (출력 전 반드시 실행)

- [ ] 첫 문장이 장면·감각으로 시작하는가 (설명·선언 아님)
- [ ] 감정을 단어로 말하지 않고 장면으로 보여줬는가
- [ ] 시선 한 문장이 글 전체를 관통하는가
- [ ] 전환(시선이 꺾이는 지점)이 있는가
- [ ] 마무리가 교훈·요약이 아니라 여운인가
- [ ] 과장형 형용사·모호한 부사·"~할 수 있습니다" 잔존 여부
- [ ] 논증 침투(교훈 선언·당위 명령·논증 나열) 여부

### 문장 품질 기준 (GOOD/BAD 예시)

| BAD (금지) | GOOD (기준) |
|-----------|------------|
| 오늘은 오래된 노트에 대해 이야기하려 한다 | 노트의 첫 장은 3년 전 날짜였다 |
| 그 순간 나는 깊은 외로움을 느꼈다 | 불 꺼진 사무실에서 모니터만 혼자 깜빡였다 |
| 결국 시간은 소중하다는 것을 깨달았다 | 노트를 덮으며, 3년이 한 권에 담긴다는 게 이상했다 |
| 우리는 가끔 멈춰서 돌아봐야 한다 | 그날 이후로 노트의 첫 장을 자주 들춰본다 |

### 산출물

초안은 대화창 텍스트로 직접 제공한다. 파일 저장은 명시 요청 시에만. 자가 점검 7항목 충족 후 출력.

## Step 4: 리라이팅 (Rewriting)

> **리라이팅 원본 보존 원칙** (`references/writing-principles.md` 참조): 리라이팅은 내용을 바꾸지 않는다. 같은 시선·같은 장면을 더 정확하고 읽기 좋은 문장으로 다듬는다. 구조 변경이 필요하면 별도 제안으로 분리한다.

> **이 단계 진입 시** `references/review-checklist.md`를 읽는다.

### 역할 전환 선언 (리라이팅 진입 조건)

이 단계에서는 쓴 사람의 시점을 내려놓는다. 독자로서, "이 장면이 보이는가, 이 시선이 전달되는가"만 판단한다. 에세이 리라이팅의 함정은 표현을 미화하다 감각을 죽이는 것이다. 더 예쁜 문장이 아니라 더 정확한 장면을 목표로 한다.

### 진행 방식

1. **점검 리포트 제시** — 4가지 점검 결과를 표로 제시
2. **사용자 확인** — 수정 방향 동의 또는 추가 지시
3. **수정본 작성** — 확인된 방향으로 전체 수정본 제시
4. **변경 요약** — 수정본 하단에 주요 변경 사항 정리

"리라이팅해줘" → 1~4 한 번에. "점검만 해줘" → 1까지만.

### 점검 항목 (상세는 review-checklist.md)

| # | 점검 영역 | 핵심 |
|---|----------|------|
| 1 | 시선 일관성 | 시선 한 문장이 처음부터 끝까지 유지되는가, 중간에 흐트러지지 않는가 |
| 2 | 장면·감각 | 감정을 설명으로 처리한 곳이 없는가, 감각 디테일이 충분한가 |
| 3 | 문장 호흡 + 금지어 | 단문·장문 교차, 종결어미, 금지어·논증 침투 잔존 |
| 4 | 여운·마무리 | 마무리가 교훈·요약으로 닫히지 않았는가, 여운이 남는가 |

### 변경 요약 포맷

```
**주요 변경 사항:**
- 시선: (변경 내용)
- 장면·감각: (변경 내용)
- 문장: (변경 내용)
- 마무리: (변경 내용)
```

## Step 5: 최종 출력 (Final Output)

### 진행 방식

1. **최종 점검** — 제목 확정, 맞춤법, [TODO] 해결, 분량 확인
2. **제목 확정** — 후보 3~5개 제시 → 사용자 선택
3. **사용자 확인** — 최종본 텍스트 확정
4. **파일 생성** — 확정 후 지정 포맷으로 생성

"최종 출력해줘" → 1~4 한 번에.

### 에세이 제목 생성 기준

칼럼 제목과 다르다. 키워드·검색을 위한 제목이 아니라 시선을 암시하는 제목이다.

(1) 시선을 한 번에 드러내지 않고 살짝 비킨다 (2) 소재의 구체적 사물·장면을 활용 가능 (3) 설명형·정보형 제목 지양 (4) 12자 내외 권장, 단 분위기를 위해 길어져도 무방

| BAD (정보형) | GOOD (시선 암시형) |
|-----------|------------|
| 오래된 노트를 보며 느낀 점 | 첫 장의 날짜 |
| 시간의 소중함에 대하여 | 한 권에 담긴 3년 |

### 산출물

최종 완성본은 사용자가 채널을 지정하지 않으면 `final.md`가 기본. `.docx`는 명시 요청 시. 단편 콘텐츠 특성상 대화창 텍스트 제공을 우선한다. 문서 생성 시 `/mnt/skills/public/docx/SKILL.md`를 읽고 따른다. 파일명·포맷 상세는 `references/output-rules.md` 참조.
