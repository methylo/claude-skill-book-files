# 네이버 블로그 정보형 글쓰기 워크플로우 (Naver Blog Info Writing)

네이버 블로그에 발행하는 정보형 글에 최적화된 5단계 글쓰기 프로세스. **검색 키워드 노출**과 **모바일 가독성** 두 축을 모든 단계에서 함께 관리한다. 워드프레스 블로그는 write-blog, 브런치는 write-brunch, 페이스북은 write-facebook, 비채널 일반 글은 write-content, 에세이는 write-essay, 장편(책)은 book-writing-pro를 사용한다.

## 네이버 블로그 플랫폼 이해

스킬의 모든 단계는 아래 플랫폼 특성을 전제로 한다. 상세 알고리즘 기준은 `references/naver-search.md`를 참조한다.

### 검색 의도 기반 노출 플랫폼

네이버 블로그는 **네이버 통합검색·스마트블록 유입이 핵심 트래픽 경로**다. 글이 검색 결과 상단 또는 스마트블록 안에 노출되려면 세 가지 조건을 만족해야 한다.

1. **출처 신뢰도(C-Rank)** — 특정 주제를 꾸준히 다룬 블로그가 그 주제에서 유리하다. 한 글 안에서도 주제 집중도가 평가된다.
2. **제목-본문 일관성과 경험(D.I.A.+)** — 제목이 약속한 정보를 본문이 충실히 제공하는지, 직접 경험·실측·후기가 담겼는지를 평가한다. 키워드 반복만으로는 저품질로 분류된다.
3. **검색 의도 세분화(스마트블록)** — "제주도 카페"가 "오션뷰 카페", "디저트 카페" 등으로 쪼개진다. 대형 키워드 하나가 아니라 **롱테일 의도 하나를 정확히 겨냥**해야 한다.

### 모바일 우선 소비

네이버 블로그 트래픽의 다수는 모바일에서 발생한다. 글은 **모바일 화면 폭(한 줄 약 18~25자)** 기준으로 읽힌다.

- 긴 문장은 모바일에서 4~5줄로 늘어져 가독성을 해친다
- 사진·이미지가 텍스트 사이에 들어가 호흡을 끊는다(글당 사진 5~15장이 일반적)
- 독자는 스크롤하며 사진과 소제목을 먼저 훑고, 필요한 부분만 정독한다
- 읽기 시간: 2~5분 (1,500~2,500자 + 사진)

### 본문 출력 형식 — 평문(마크다운 기호 제거)

**네이버 스마트에디터는 마크다운을 지원하지 않는다.** `##`, `**`, `-` 같은 기호를 붙여넣으면 본문에 그대로 노출된다. 따라서 이 스킬의 본문 산출물은 **마크다운 기호를 제거한 평문**으로 작성한다.

- 소제목: 기호 없이 별도 줄에 배치. 사용자가 에디터에서 제목 스타일·굵게를 직접 적용
- 강조: `**굵게**` 대신 강조할 문장을 짧은 독립 단락으로 배치하거나, 따옴표·줄바꿈으로 시선을 모은다
- 목록: 에디터의 줄바꿈으로 표현. 부득이하게 번호가 필요하면 `1.` 대신 `1)` 같은 평문 표기 사용
- 본문 안에 마커는 `[이미지: 설명]` 형식만 허용한다(사진 삽입 위치 표시용)

### 네이버 정보글의 특징

- 정보 밀도와 사진 비중의 균형. 글만 길고 사진이 없으면 이탈, 사진만 많고 정보가 없으면 저품질
- 제목과 본문이 같은 의도를 가리킨다. 낚시성 제목은 체류시간 하락으로 역효과
- 독자가 이 글을 읽은 뒤 다른 글을 더 찾지 않도록 의도 하나를 완결한다

## 전체 흐름

```
Step 1: 키워드·검색의도 설계 → Step 2: 구조 설계 → Step 3: 초안 작성 → Step 4: 리라이팅 → Step 5: 발행 준비
```

사용자의 상태에 따라 적절한 단계부터 시작한다.
- 주제만 있음 → Step 1부터
- 키워드·구조 있음 → Step 3부터
- 초안 있음 → Step 4부터
- 다른 채널 글을 네이버용으로 변환 → Step 2부터

### Step 간 전환 규칙

각 Step 완료 후, 다음 Step으로 넘어가기 전에 사용자 확인을 받는다.

| 전환 | 확인 방식 |
|------|----------|
| Step 1 → 2 | 핵심 키워드·검색 의도·독자·글 유형을 요약 제시하고, 확정 여부를 확인한 뒤 구조 설계로 진행한다 |
| Step 2 → 3 | 아웃라인(소제목 포함)·제목 후보·사진 배치 계획을 제시하고, 수정이 필요한지 확인한 뒤 초안 작성으로 진행한다 |
| Step 3 → 4 | 초안을 제시하고, 방향 수정이나 추가 요청이 있는지 확인한 뒤 리라이팅으로 진행한다 |
| Step 4 → 5 | 수정본을 제시하고, 추가 수정이 필요한지 확인한 뒤 발행 준비로 진행한다 |

사용자가 "끝까지 진행해줘" 또는 "한 번에 해줘"라고 요청한 경우, 확인 없이 연속 진행한다.

## 공통 집필 원칙

### 문체 기준

- 표준어 사용
- 종결어미는 **'~합니다'체 고정** (별도 지정 없으면 변경하지 않는다)
- 축약형 금지 ("됐습니다" → "되었습니다")
- 문장은 모바일 가독성을 위해 **15~25단어 이내, 한 문장 한 정보**로 작성한다
- 문장은 능동형을 기본으로 한다
- 감정적 표현·감탄형 문장 지양. 차분하고 설명적인 톤 유지

### 모바일 가독성 원칙 (네이버 특화 핵심)

세부 기준은 `references/mobile-readability.md`를 참조한다. 핵심은 다음과 같다.

- **문단은 2~3문장.** 워드프레스 블로그(2~5문장)보다 짧게 끊는다. 모바일 화면에서 한 문단이 6줄을 넘지 않게 한다
- **의미 단위마다 빈 줄(엔터)로 단락을 분리**한다. 호흡이 길어지는 지점에서 끊는다
- **한 문장이 모바일에서 3줄을 넘으면 분리**를 검토한다
- 강조는 마크다운 굵게가 아니라 **짧은 독립 단락**으로 처리한다
- 소제목 사이 본문은 3~5단락 이내로 유지하고, 그 사이에 사진 1장 이상을 배치한다

### 서술 전략

- 글의 첫 문장: **독자의 검색 의도·문제 상황**으로 시작. 정의·인사말·메타 서술로 시작하지 않음
- 설명 순서: **상황 → 기준 → 방법·결과**
- 소제목은 기능명 나열이 아닌 **검색 의도를 담은 문장 또는 질문형**으로 작성
- 직접 경험·실측·후기를 본문에 명시한다(D.I.A.+ 평가 축)
- 마무리는 요약이 아니라 **핵심 정보 압축 + 독자의 다음 판단 기준** 제시

### 글쓰기 금지어 규칙

모든 문장은 **판단·기준·결과**가 드러나야 한다. 위반 시 자가 수정 후 응답한다.

**① 과장형 형용사 금지**
금지어: 혁신적인, 획기적인, 창의적인, 강력한, 완벽한, 최고의, 탁월한, 뛰어난
→ 무엇이 어떻게 다른지, 수치·사례로 설명한다.

**② 모호한 부사 금지**
금지어: 매우, 굉장히, 상당히, 꽤, 쉽게, 빠르게, 간편하게, 효율적으로
→ 시간·단계·수치·조건으로 대체한다.

**③ 추측·완곡 표현 금지**
금지어: ~할 수 있습니다, ~일 수 있습니다, ~라고 볼 수 있습니다, 어느 정도, 부분적으로, 다소
→ 단정형으로 서술한다. 조건이 있다면 조건을 먼저 제시한다.

**④ 불필요한 여유 연결어 금지**
금지어: 전반적으로 볼 때, 일반적으로 말하면, 어떤 면에서 보면, 이러한 측면에서, 결과적으로
→ 근거 → 주장 구조로 직접 연결한다.

**⑤ 추상 명사 중심 문장 지양**
주의어: 중요성, 필요성, 가능성, 효과, 가치, 측면, 부분
→ 동사 중심 문장으로 전환. 장면·행동·결과로 구체화한다.

**⑥ AI 흔적 조합 금지**
부사 + 형용사 + 가능성 표현 + 추상 명사 패턴은 금지한다.

### 금지 요소

- "안녕하세요, 오늘은 ~에 대해 알아보겠습니다" 식의 인사·메타 서술 도입
- 키워드를 부자연스럽게 반복 삽입하는 행위(저품질 신호)
- 제목과 본문 의도가 어긋나는 낚시성 구성
- 정보 없이 사진과 감탄사만 채우는 구성
- 근거 없는 과장·미사여구
- **본문 내 마크다운 기호(`#`, `**`, `-`, `>` 등)** — 평문으로 출력한다
- 문단을 6줄 이상으로 늘어뜨리는 모바일 비친화 단락

## Step 1: 키워드·검색의도 설계 (Keyword & Search Intent Design)

글을 쓰기 전에 다음을 명확히 한다. 상세 기준은 `references/naver-search.md`를 참조한다.

### 수집 항목

| 항목 | 질문 | 예시 |
|------|------|------|
| **주제** | 무엇에 대해 쓰는가? | AI 글쓰기 도구 비교, 테슬라 충전 방법, 책쓰기 강의 후기 |
| **핵심 키워드** | 독자가 네이버에 검색할 때 입력하는 말은? | "클로드 코워크 사용법", "테슬라 모델3 완속충전" |
| **검색 의도(스마트블록)** | 그 키워드가 어떤 하위 의도로 쪼개지는가? 어떤 의도 하나를 겨냥하는가? | "사용법" → 설치·기본조작·실전활용 중 '실전활용' |
| **독자** | 누가 검색하는가? 어떤 상태에서 검색하는가? | 클로드를 막 시작한 비개발자, 구매 직후 충전이 막막한 차주 |
| **글 유형** | 어떤 형식인가? | 방법·튜토리얼 / 비교·선택 / 후기·체험 / 정보 정리 / Q&A 해설 |
| **경험 근거** | 직접 경험·실측·후기가 있는가? (D.I.A.+ 핵심) | 실제 사용 화면, 직접 측정한 수치, 현장 관찰 |

### 키워드 선정 기준

- **핵심 키워드 1개 + 보조 키워드 2~3개**를 선정한다
- 대형 키워드보다 **경쟁이 낮은 롱테일 키워드**부터 겨냥한다(스마트블록 진입 유리)
- 핵심 키워드를 실제로 네이버에 검색해, 자동 생성되는 스마트블록 주제를 확인하고 그중 하나를 겨냥한다
- 키워드는 **제목 + 첫 단락 + 소제목 1곳 이상**에 자연스럽게 배치한다
- 키워드 밀도보다 **제목-본문 의도 일관성(D.I.A.+)**을 우선한다

### 산출물

수집 항목 + 키워드 배치 계획을 요약 정리해 사용자에게 제시한다. 사용자 확인 후 Step 2로 진행한다.

## Step 2: 구조 설계 (Structure Design)

### 정보글 구조 패턴

글 유형에 따라 아래 구조를 기본으로 하되, 사용자 의도에 맞게 조정한다. 상세 템플릿은 `templates/post-structure.md`를 참조한다. 모든 소제목은 **평문**으로 작성하며, 검색 의도를 담는다.

**방법·튜토리얼형:**
```
도입: 검색 의도 확인 + 이 글이 답하는 범위 (3~4문장)
소제목: 시작 전 알아둘 것 / 준비물·전제
소제목: 단계별 방법 (1단계, 2단계… 사진 동반)
소제목: 자주 막히는 지점과 해결
마무리: 핵심 단계 압축 + 다음 행동
```

**비교·선택형:**
```
도입: 무엇과 무엇을 왜 비교하는가 (검색 의도)
소제목: 비교 기준 제시
소제목: A의 특징과 적합한 상황
소제목: B의 특징과 적합한 상황
소제목: 상황별 선택 가이드
마무리: 결론 한 줄 + 판단 기준
```

**후기·체험형:**
```
도입: 어떤 상황에서 이걸 쓰게 됐는가
소제목: 실제 사용·방문 과정 (사진 중심)
소제목: 좋았던 점 / 아쉬운 점 (직접 경험 근거)
소제목: 이런 사람에게 추천
마무리: 종합 평가 + 추천 기준
```

### 소제목 설계 규칙

네이버는 본문 소제목도 검색·체류 평가에 반영한다. 독자가 소제목과 사진만 훑어도 글의 골격을 파악할 수 있어야 한다.

- 소제목은 3~6개. 정보글 한 편의 핵심 블록을 나눈다
- 소제목은 **검색 의도형 문장 또는 질문형**으로 작성한다
- 명사 나열 금지 (예: ✕ "충전 방법" → ○ "집에서 완속충전하는 순서")
- 소제목과 소제목 사이 본문은 3~5단락 이내, 사이마다 사진 1장 이상

### 사진 배치 계획

네이버 정보글은 사진 비중이 크다. 구조 설계 단계에서 사진 위치를 미리 잡는다.

- 도입 직후 대표 사진(썸네일 후보) 1장
- 각 소제목 블록마다 1~3장
- 단계·과정 설명은 사진과 1:1 대응
- 본문에는 `[이미지: 설명]` 마커로 위치를 표시한다

### 제목 설계

네이버 검색 결과에서 클릭과 D.I.A.+ 평가를 동시에 좌우한다. 상세 규칙은 `references/naver-search.md`를 참조한다.

- 핵심 키워드를 제목 앞부분에 자연스럽게 포함한다
- 제목이 약속한 정보를 본문이 반드시 제공한다(낚시 금지)
- 25~35자 권장(모바일 검색 결과에서 잘리지 않는 범위)
- 숫자·연도·구체 조건을 넣으면 클릭률이 오른다 (예: "2026", "3가지", "초보용")

제목 후보를 **5개** 생성한다.

### 산출물

아웃라인(소제목 포함) + 제목 후보 5개 + 사진 배치 계획 + 키워드 배치 계획을 사용자에게 제시한다. 사용자 확인 후 Step 3으로 진행한다.

## Step 3: 초안 작성 (First Draft)

### 초안 작성 규칙

- Step 2에서 확정된 구조와 소제목을 따라 작성한다
- 공통 집필 원칙(서술 전략, 문체 기준, 금지어 규칙)과 모바일 가독성 원칙을 적용한다
- **본문은 평문으로 작성한다.** 마크다운 기호(`#`, `**`, `-`)를 쓰지 않는다
- 소제목은 기호 없이 독립 줄에 배치한다
- **문단은 2~3문장.** 의미 단위마다 빈 줄로 분리한다
- 분량: 공백 포함 **1,500~2,500자**
- 사진 위치: `[이미지: 설명]` 마커로 표시한다(Step 2 계획 반영)
- 도입부 3~4문장에 집중한다 — 검색 결과 미리보기와 첫 화면 노출 구간

### 도입부 설계

검색 유입 독자는 첫 화면에서 이 글이 자신의 검색 의도에 맞는지 판단한다. 다음 중 하나로 시작한다.

| 방식 | 예시 | 효과 |
|------|------|------|
| 검색 의도 확인 | "테슬라 모델3를 받고 가장 막막한 건 집에서 충전하는 방법입니다." | 의도 적중, 정독 유도 |
| 문제 상황 | "완속충전기를 설치했는데 앱에서 충전이 시작되지 않았습니다." | 같은 문제 독자 공감 |
| 결론 먼저 | "결론부터 말하면, 비개발자는 코워크부터 시작하는 편이 낫습니다." | 빠른 답 제공, 체류 유지 |

**금지되는 도입:**
- "안녕하세요, ○○입니다. 오늘은 ~"
- "~란 무엇일까요? ~는 ~를 의미합니다" (사전식 정의)
- "최근 ~가 화제입니다" (뉴스 리드식)

### 결론 설계

요약이 아니라 **핵심 정보 압축 + 독자의 다음 행동 기준**으로 마무리한다.

- 3~5문장 이내
- 본론 내용을 반복하지 않는다
- 독자가 이 글을 읽고 무엇을 기준으로 판단·행동하면 되는지 명확히 한다

### 산출물

- 초안은 **대화창 텍스트로 직접 제공**한다(파일 생성하지 않음)
- 평문 형식(마크다운 기호 없음)으로 제공한다
- 사용자가 파일을 명시적으로 요청한 경우에만 저장한다
- 사용자 확인 후 Step 4로 진행한다

## Step 4: 리라이팅 (Rewriting)

> **리라이팅 원본 보존 원칙**: 리라이팅은 내용을 바꾸지 않는다. 같은 내용을 더 정확하고 모바일에서 읽기 좋은 문장으로 다듬는다. 구조 변경이 필요하면 별도 제안으로 분리한다.

### 역할 전환 선언 (리라이팅 진입 조건)

이 단계에서는 작성자 시점을 내려놓는다. 편집자로서 작성 의도를 참고하지 않고 **모바일 화면으로 글을 읽는 독자 시점**에서만 판단한다. "왜 이렇게 썼는가"가 아니라 "모바일에서 읽었을 때 작동하는가"를 기준으로 점검한다.

초안을 5가지 관점에서 점검하고 수정한다.

### 진행 방식

1. **점검 리포트 제시** — 5가지 점검 결과를 표로 보여준다
2. **사용자 확인** — 수정 방향에 동의 또는 추가 지시를 받는다
3. **수정본 작성** — 확인된 방향으로 전체 수정본을 평문으로 제시한다
4. **변경 요약** — 수정본 하단에 주요 변경 사항을 정리한다

사용자가 "리라이팅해줘"라고만 요청한 경우, 1~4를 한 번에 진행한다.

### 점검 1: 도입부·검색 의도 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | 첫 문장이 검색 의도·문제 상황·결론 중 하나로 시작하는가 | 인사말·정의·메타 서술이면 교체 |
| 2 | 첫 3~4문장이 검색 의도와 맞닿는가 | 의도 적중 문장으로 교체 |
| 3 | 제목이 약속한 정보를 본문이 제공하는가(D.I.A.+) | 제목-본문 의도 불일치 시 한쪽 수정 |

### 점검 2: 모바일 가독성 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | 문단이 2~3문장 이내인가 | 6줄 넘는 문단 분리 |
| 2 | 의미 단위마다 빈 줄로 분리되었는가 | 호흡 긴 지점에 단락 분리 추가 |
| 3 | 한 문장이 모바일 3줄을 넘지 않는가 | 긴 문장 분리 |
| 4 | 사진 위치 마커가 소제목 블록마다 배치되었는가 | `[이미지]` 마커 점검·추가 |

### 점검 3: 문장·금지어 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | "~할 수 있습니다"가 있는가 | 단정형 전환 |
| 2 | "매우, 쉽게, 빠르게"가 있는가 | 수치·조건·단계로 대체 |
| 3 | 과장형 형용사가 근거 없이 쓰였는가 | 비교 기준·수치로 교체 |
| 4 | 추상 명사가 문장 중심에 있는가 | 동사 중심 문장으로 전환 |
| 5 | 축약형("됐")이 있는가 | "되었"으로 교체 |
| 6 | AI 흔적 조합(부사+형용사+가능성+추상명사)이 있는가 | 해체 후 재구성 |

### 점검 4: 키워드·구조 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | 핵심 키워드가 제목·첫 단락·소제목에 자연스럽게 있는가 | 누락 시 자연스럽게 추가 |
| 2 | 키워드가 부자연스럽게 반복되지 않는가 | 과다 반복 제거(저품질 회피) |
| 3 | 소제목만 읽어도 골격이 파악되는가 | 모호한 소제목 재작성 |
| 4 | 직접 경험·실측·후기가 본문에 있는가 | 경험 근거 보강 |

### 점검 5: 평문·발행 형식 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | 본문에 마크다운 기호(`#`,`**`,`-`,`>`)가 남아 있는가 | 평문으로 전환 |
| 2 | 분량이 1,500~2,500자 범위인가 | ±20% 이내로 조정 |
| 3 | 종결어미가 '~합니다'체로 일관적인가 | 통일 |
| 4 | 마무리가 정보 압축 + 행동 기준으로 끝나는가 | 요약형·감상형이면 전환 |

### 변경 요약 표준 포맷

```
주요 변경 사항
- 도입부/검색의도: (변경 내용)
- 모바일 가독성: (변경 내용)
- 문장: (변경 내용)
- 키워드/구조: (변경 내용)
- 평문/발행 형식: (변경 내용)
```

## Step 5: 발행 준비 (Publish Ready)

Step 4 수정본을 네이버 발행 수준으로 마무리한다. 상세 점검표는 `templates/meta-template.md`를 참조한다.

### 진행 방식

1. **최종 점검 실행** — 아래 항목을 점검하고 결과를 사용자에게 제시한다
2. **제목 확정** — 후보를 제시하고 사용자가 선택한다
3. **발행 메타 정보 작성** — 태그, 대표 사진 방향, 키워드 최종 배치
4. **사용자 확인** — 최종본을 보여주고 확정 여부를 확인한다
5. **산출** — 확정 후 평문 본문을 제공한다(기본은 대화창 텍스트, 요청 시 파일)

### 최종 점검 항목

| # | 점검 항목 | 기준 |
|---|----------|------|
| 1 | 제목 확정 | 후보 5개 중 선택. 핵심 키워드 포함, 25~35자, 제목-본문 의도 일치 |
| 2 | 맞춤법·문법 교정 | 한국어 맞춤법, 띄어쓰기, 외래어 표기법, 문장부호 |
| 3 | 태그 선정 | 5~10개. 핵심·보조 키워드와 연관어 포함 |
| 4 | 대표 사진 방향 | 글 주제에 맞는 사진 콘셉트 제안(직접 생성하지 않음) |
| 5 | 키워드 최종 배치 | 제목·첫 단락·소제목에 자연 배치, 과다 반복 없음 |
| 6 | 분량 최종 확인 | 1,500~2,500자(±20%) |
| 7 | 평문 확인 | 마크다운 기호 잔존 여부 점검 |
| 8 | `[이미지]` 마커 | 모든 마커가 실제 삽입 안내로 정리되었는지 확인 |

### 산출물

- 최종본은 **평문 대화창 텍스트**로 제공한다(네이버 스마트에디터 붙여넣기용)
- 사용자가 파일을 요청한 경우 `.docx`로 저장한다. `.docx` 생성 시 `/mnt/skills/public/docx/SKILL.md`를 읽고 따른다

최종본과 함께 아래 **발행 체크리스트**를 제시한다.

```
네이버 블로그 발행 체크리스트
- 제목 (핵심 키워드 포함, 25~35자)
- 대표 사진 (썸네일)
- 본문 사진 5~15장 배치
- 태그 5~10개
- 카테고리 지정
- 키워드 제목·첫단락·소제목 배치 확인
- 평문 확인(마크다운 기호 없음)
- 발행
```

## 분량 통제 규칙

### 원문 보존 강도 레벨

사용자의 요청 동사에 따라 보존 강도를 자동 판별한다.

| 레벨 | 트리거 | 허용 범위 | 금지 행위 |
|------|--------|----------|----------|
| **L1 교정** | "다듬어줘", "교정해줘", "수정해줘" | 맞춤법·띄어쓰기·종결어미 통일만 | 문장 분리·병합, 새 문장 추가, 문단 재배치 |
| **L2 정리** | "정리해줘", "깔끔하게", "보강해줘" | 문장 분리·접속 보강, 지정 부분 내용 추가 | 구조 재배치, 미지정 부분 수정 |
| **L3 리라이팅** | "리라이팅해줘", "다시 써줘" | 구조 재배치·문장 교체·패턴 적용 허용 | 분량 120% 초과(초과 시 사유 확인) |

- 사용자가 레벨을 명시하지 않으면 트리거 동사로 자동 판별한다
- 수정 결과물이 2,500자를 초과하면 초과 사유를 먼저 확인한다
