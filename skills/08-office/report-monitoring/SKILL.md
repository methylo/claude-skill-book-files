# 월간 모니터링 보고서 스킬

데이터를 입력하면 구조화된 월간 보고서 초안을 생성하는 스킬이다.

## 이 스킬이 하는 일

사용자가 업무 데이터(표, 수치, 메모)를 붙여넣으면, 4단계 구조의 보고서 초안을 작성한다. AI가 만든 초안은 출발점이다. 사용자가 사실관계를 확인하고 수정하여 최종본을 완성한다.

## 전체 작업 흐름

이 스킬은 4단계로 진행된다. 각 단계가 끝날 때마다 현재 위치와 다음 할 일을 안내한다.

```
1단계: 입력 확인 — 데이터를 받고 보고서 방향을 정한다
   ↓
2단계: 보고서 초안 작성 — 4단계 구조로 초안을 만든다
   ↓
3단계: 검토 및 수정 — 사용자가 확인하고 수정을 요청한다
   ↓
4단계: 파일 저장 — 워드(.docx) 또는 한글(.hwpx)로 저장한다
```

## 개인정보 보호 원칙

보고서 작성 전 반드시 확인한다.

- 실명, 주민등록번호, 장애등급, 연락처 등 개인 식별 정보는 입력하지 않는다
- 사례를 언급할 때는 "이용자 A", "대상자 1" 등 가명을 사용한다
- 사용자가 실명이나 민감 정보를 입력한 경우, 가명 처리를 안내한 뒤 진행한다

---

## 1단계: 입력 확인

사용자에게 아래 정보를 확인한다. 모든 항목이 없어도 있는 것만으로 진행할 수 있다.

**필수 입력:**
- 보고서 제목 또는 주제 (예: "4월 활동지원서비스 모니터링 보고서")
- 데이터 (표, 수치, 텍스트 중 어떤 형태든 가능)

**선택 입력:**
- 보고 대상 (상급 기관, 내부 회의 등)
- 이전 달 보고서 또는 비교 기준
- 강조하고 싶은 이슈나 성과

사용자가 데이터만 붙여넣고 별다른 설명이 없으면, 데이터를 분석하여 보고서 주제와 구조를 먼저 제안한다.

**1단계 완료 후 안내 멘트:**

> 데이터를 확인했습니다. 지금부터 보고서 초안을 작성합니다.
>
> **진행 상황:** 1단계(입력 확인) ✅ → **2단계(초안 작성)** 진행 중 → 3단계(검토) → 4단계(파일 저장)

---

## 2단계: 보고서 초안 작성

아래 4단계 구조로 보고서를 작성한다.

```
[보고서 제목]
작성일: YYYY년 MM월 DD일
작성자: (사용자가 지정하면 기입, 미지정 시 공란)

1. 현황 요약
   - 핵심 수치 3~5개를 문장으로 정리
   - 전월 대비 변화가 있으면 비교 포함
   - 표로 정리할 수 있는 데이터는 표로 제시

2. 주요 이슈
   - 데이터에서 도출되는 문제점 또는 특이사항 2~3건
   - 각 이슈에 근거 수치를 함께 제시

3. 조치 사항
   - 각 이슈에 대한 대응 방안
   - 이미 조치한 내용과 향후 계획을 구분

4. 다음 달 계획
   - 중점 관리 항목 2~3건
   - 구체적 일정이나 목표 수치가 있으면 포함
```

초안을 작성한 뒤, 하네스 규칙에 따라 자가 점검을 실행한다(아래 "하네스 규칙" 참조). 점검을 통과한 초안만 사용자에게 제시한다.

**2단계 완료 후 안내 멘트:**

> 보고서 초안이 완성되었습니다.
>
> **진행 상황:** 1단계(입력 확인) ✅ → 2단계(초안 작성) ✅ → **3단계(검토)** ◀ 현재 → 4단계(파일 저장)
>
> **지금 할 일:** 아래 초안을 확인해 주세요.
> - 수치나 사실관계가 다른 부분이 있으면 알려주세요
> - 추가하거나 빼고 싶은 내용이 있으면 말씀해 주세요
> - 톤이나 분량 조정이 필요하면 요청해 주세요
>
> **다음 단계:** 내용이 확정되면, 워드(.docx) 또는 한글(.hwpx)로 파일을 저장합니다.

---

## 3단계: 검토 및 수정

사용자가 수정을 요청하면 반영한다. 수정된 내용에 대해서도 하네스 규칙 점검을 실행한다.

사용자가 "이대로 좋다", "확인했다", "저장해줘" 등 확정 의사를 밝히면 4단계로 넘어간다.

**3단계 완료 후 안내 멘트:**

> 보고서 내용이 확정되었습니다.
>
> **진행 상황:** 1단계 ✅ → 2단계 ✅ → 3단계 ✅ → **4단계(파일 저장)** ◀ 현재
>
> 보고서를 파일로 저장할까요? 아래에서 형식을 선택해 주세요.
> - **워드(.docx)** — MS 워드에서 편집 가능
> - **한글(.hwpx)** — 한컴오피스에서 편집 가능
> - **저장 안 함** — 위 텍스트를 직접 복사해서 사용

---

## 4단계: 파일 저장

사용자가 선택한 포맷으로 파일을 생성한다.

- **워드(.docx)** 선택 시: docx 스킬을 사용하여 보고서를 워드 문서로 생성
- **한글(.hwpx)** 선택 시: hwpx 스킬을 사용하여 보고서를 한글 문서로 생성
- 사용자가 파일 저장을 원하지 않으면 대화창 텍스트 그대로 종료

파일명 기본 형식: `YYYY년 MM월 [보고서 제목].docx` 또는 `.hwpx`

**4단계 완료 후 안내 멘트:**

> 파일이 생성되었습니다.
>
> **전체 진행:** 1단계 ✅ → 2단계 ✅ → 3단계 ✅ → 4단계 ✅ 완료
>
> 같은 데이터로 다른 형태의 문서가 필요하면 알려주세요.
> - "짧게 요약해줘" → 반 페이지 요약 보고
> - "발표용으로 바꿔줘" → 슬라이드용 불릿 포인트
> - "건의서로 바꿔줘" → 현황-문제점-개선안-기대효과 구조

---

## 작성 규칙

### 문체
- 공공기관 보고서에 적합한 간결한 문어체를 사용한다
- "~하였다", "~이다" 종결. 경어체가 필요하면 "~하였습니다"
- 한 문장은 40자 이내로 짧게 쓴다

### 수치 표현
- 데이터가 있으면 반드시 수치를 포함한다 (예: "전월 대비 12% 증가")
- 비율, 건수, 인원 등 단위를 명시한다
- 표로 정리하면 읽기 쉬운 데이터는 표를 사용한다

### 분량
- 기본 분량: A4 1~2페이지
- 사용자가 분량을 지정하면 그에 맞춘다

---

## 입력 데이터 처리

사용자가 다양한 형태로 데이터를 줄 수 있다. 각 경우에 맞게 처리한다.

**표 데이터:** 그대로 분석하여 현황 요약에 핵심 수치를 추출한다
**텍스트 메모:** 구조화되지 않은 메모에서 핵심 내용을 뽑아 보고서 구조에 배치한다
**이전 보고서:** 형식과 톤을 참조하여 일관성을 유지한다
**복수 데이터:** 여러 출처의 데이터를 통합하여 하나의 보고서로 정리한다

---

## 보고서 유형 변형

기본은 월간 모니터링 보고서이지만, 사용자가 요청하면 같은 데이터로 다른 형태의 문서도 작성할 수 있다.

- **요약 보고:** 핵심 수치와 이슈만 반 페이지로 압축
- **발표용 요약:** 슬라이드에 넣을 수 있는 불릿 포인트 형태
- **상급 기관 보고:** 현황-문제점-개선안-기대효과 구조의 건의서 형태

사용자가 "짧게", "발표용으로", "건의서로" 등의 키워드를 쓰면 해당 변형을 적용한다.

---

## 하네스 규칙

### 완성 조건

보고서 초안 완성 후, 아래 항목을 점검한다. 모든 항목을 통과해야 사용자에게 제시한다.

**금지어 — 아래 표현은 사용하지 않는다:**
- 혁신적인, 획기적인, 완벽한
- 매우, 굉장히, 상당히 (수치로 대체한다. "매우 증가" → "50% 증가")
- ~할 수 있습니다 + 추상명사 조합 (예: "효율성을 높일 수 있습니다" → 구체적 수치나 행동으로 대체)

**수치 근거 — 주장에는 반드시 근거를 붙인다:**
- "증가하였다" → "48명에서 52명으로 4명(8.3%) 증가하였다"
- "개선되었다" → "만족도가 4.2점에서 4.4점으로 상승하였다"
- 근거 없이 판단만 쓴 문장이 있으면 데이터를 확인하여 수치를 추가한다

**AI 흔적 제거 — 아래 패턴이 나타나지 않도록 한다:**
- 같은 문장 구조의 반복 (예: 연속 3문장이 "~하였다. ~하였다. ~하였다.")
- 불필요한 접속사 나열 ("또한", "아울러", "더불어"가 한 섹션에 3회 이상)
- "~것으로 보인다", "~것으로 판단된다"의 과도한 사용 (한 보고서에 2회 이내)

**문체 일관성:**
- 종결어미 통일: "~하였다"체 또는 "~하였습니다"체 중 하나로 통일
- 축약형 금지: "됐다" → "되었다", "했다" → "하였다"

### 자가 평가 루프

1. 초안 완성 후 위 완성 조건 체크리스트를 실행한다
2. 미달 항목이 있으면 해당 항목만 수정한 뒤 재점검한다 (최대 2회)
3. 2회 후에도 미달이면 미달 항목과 사유를 사용자에게 보고한다
4. 점검 결과를 보고서 말미에 간략히 표기한다

점검 결과 표기 예시:
> 점검 완료: 금지어 0건 / 수치 근거 확인 / AI 흔적 0건 / 문체 통일(~하였다)

## 샘플 데이터

연습용 입력은 `sample-monthly-data.md`에 있다. 사용자가 "샘플로 해 봐"라고 하면 이 파일을 읽어 보고서를 만든다.
